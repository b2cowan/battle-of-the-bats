Support Console Feedback Reply Walk

One question: can support read a feedback item as a record, triage it behind one pencil, and answer the person by email, with only the right roles holding the Reply button? The list lost its dropdowns and gained a Replied column; each item has a page with the conversation on it. Tick what holds, and write what does not. Your ticks stay in this browser; the paste-back at the foot gathers them for the chat. Walk 1 (§391) is the sent-email log; walk 3 (§393) is Status and Errors.

Before you start (about 10 minutes, once)

The console is at http://localhost:3000/platform-admin/login. Walk as Support unless a section says otherwise (Support has both the pencil and the Reply button); use a private window for each other role.

  1. Send one feedback item as a customer. In a private window sign in at http://localhost:3000/auth/login as the club owner uat-owner@uat-test-org.local, open the account menu at the top right, and choose Send feedback. Choose Bug, Category Registrations, Short summary Walk 2: the Registrations page shows an error, and any description. Send it. Do not send a second one yet.
  2. Does dev have a mail key? Open .env.local. If RESEND_API_KEY= is empty (it was when this walk was written), nothing leaves the machine: a reply is refused with “This site has no mail key, so nothing was sent.”, which is the failure the walk can provoke safely. What follows a successful send (the item moving to Acknowledged, leaving Today’s New feedback, the sent row in the conversation) can only be seen with a key, so those steps carry a second box, “Held”, and are checked at the release with one real reply. If you do add a key and restart, the account you reply to must be an inbox you own: sign the feedback in as an account whose address is yours.
  3. An anonymous and an old item. Two steps want an item sent without signing in and one older than 90 days. Dev usually holds a few from earlier testing (the list in section 1 shows them with “Not signed in”). If dev has none, tick “Held” on those steps.

⚠ The first section reads the list and the record before anything is changed. Section 3 sends nothing (no key) and section 4 changes this item’s triage; nobody is emailed by triage. The drawings this walk checks against: Support Console Stage 5, drawing D and the failure table in G.
