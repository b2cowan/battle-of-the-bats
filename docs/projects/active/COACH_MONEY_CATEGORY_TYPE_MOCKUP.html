The category reads
smaller than its lines

Owner, on the Budget Plan's By period grid: why is TOURNAMENTS smaller than Entry Fees? It is, and it is on the List view too. Three ways out, drawn at true size.

Why it happens

A category name is drawn as a taxonomy label — small, bold, uppercase, letter-spaced — because it comes from a fixed library. A line name is drawn as the coach's own words, at reading size in sentence case. The intent was to keep those two things visibly different, and that part works.

What was never checked is the resulting height. Uppercase has no ascenders or descenders, so at 0.74rem its cap-height lands around 0.52rem — shorter than the 0.59rem cap-height of a 0.84rem sentence-case line beneath it. The row that groups four others is physically the smallest text in the group.

Not new — and now cheap to change

Both the plan's grid and its List view already did this before the table pass; the convention was carried forward untouched. Because that pass put both views on one shared category treatment, this is now one value in one place rather than two independent edits that could disagree again.

What each costs

A — leave it. Nothing changes, and the small-caps eyebrow stays consistent with the tab bar, the summary labels and every other label in the portal. The hierarchy keeps reading backwards.

B — match the size. Keeps the convention and fixes the inversion. Category and line sit at the same size; uppercase, weight and letter-spacing carry the difference instead of size. Applies to both Budget Plan views and Budget vs. Actual's category view in one edit, so the three stay agreed.

C — invert it properly. The clearest hierarchy, and the biggest departure: it makes a category name look like a heading a coach wrote rather than a library label, and it is the only option that adds a new band of colour to a screen that already has a total row.
