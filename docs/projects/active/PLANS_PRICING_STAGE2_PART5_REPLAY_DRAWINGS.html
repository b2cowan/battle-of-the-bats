Build note. The console’s confirm window already has the refusal shape (no main button, Close in place of Cancel). It closes as soon as an action succeeds, so these four result states are new: the same window stays open and turns into the answer. Lime marks the one main action in each.

Every replay leaves one line in the change log, written before anything runs. If the line cannot be written, nothing runs (the last refusal in tab 2). If the run then fails, a second line says so and names the first. The Stripe page also remembers: a replayed update leaves the failing list and says who finished it.

Replay has a narrower job than the ruling suggests, and one update type is not harmless to run twice. Stripe already retries a failing delivery on its own for a few days, so a replay is for updates it gave up on, updates set aside because the club was not linked yet, and a re-run after we fixed our own fault. That is worth having, and it is small. I have drawn it small.

What the code says (checked 2026-11-08)

Trial-ending email Repeats

When the product runs a “trial ending soon” update it emails the club’s owner, with nothing to stop a second email. The two welcome-back emails only go when the club was cancelled, so a replay after it is active does not repeat them. Ask 1.

No preview exists Gap

The handler runs and writes; it does not offer a “what would change” mode, and reports only a one-word result. Before and After is the club’s record read twice. Ask 3.

Nothing is stored As ruled

A replay fetches the update from Stripe again by its id. Stripe keeps updates for about 30 days, so an older one cannot be replayed. That figure is Stripe’s own limit and I will confirm it against their documentation before building.

The receiver refuses repeats Build note

Live deliveries treat a finished update as a duplicate, which is why a replay cannot go through the same door. It must take the same claim a live delivery takes, so a replay and Stripe’s own retry cannot run at once. This is the “harmless the second time” proof the ruling asks for, and the build stops if it cannot be shown.
