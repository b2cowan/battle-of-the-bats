Every public tournament page, one layout

Written 2026-11-05. Test data only, on the dev database. About 70 minutes. One purpose: clicking through every public tournament page on a desk, the content starts, stops and spaces itself the same way, and a game, a list, a link, a heading and “live” look the same on every page; a phone keeps its ruled layouts.

What this walk is for

The layout standard (Parts 1 to 4) put every public tournament page on one 960 px column, with one game card, one link row, three heading sizes, one toolbar and one green “live”. This is the first look at all of it together, including every state of a game’s page and a team’s page, News and Register, on a computer and on a phone.

Three calls you made are in this build and are not re-asked here: a team’s own name stays bold on its page even while its game is live; the record card starts level with the first game card; News headings are sentence case with no icons. One more you made on 2026-11-05: Playoffs’ “Live now” game has no pill under its heading (the green edge says it).

It passes when

  • A and B: on a computer, every page’s content starts at the same left edge, stops at the same width, sits the same distance under the band and spaces its sections the same way. A game, a list row, a link row, a heading and “live” look the same wherever they appear. No page has a back link.
  • C and D: every state of a game’s page and a team’s page reads correctly, on a computer and on a phone.
  • E: News and Register sit on the same column, with the same headings.
  • F and G: on a phone every page keeps its ruled layout with nothing scrolling sideways; between 1,024 and 1,199 px wide the two-column pages stack.

Before you start

Setup, not checked. Some steps change the test game; they say when to ask Claude. You can also paste the command shown under a step into a terminal in the project folder.

Where
http://localhost:3000 on your computer, dev server running (ask Claude first: step S1). Use a private window so a sign-in does not change what you see. No sign-in is needed anywhere in this walk.
On a phone
Either your phone on the same Wi-Fi, at your computer’s address on the network (last walk: http://192.168.2.200:3000), or the browser window narrowed to about 390 px wide. Where a step names a long name, use 397 px.
Window sizes
“On a desk” means a window at least 1,200 px wide (the two columns sit side by side from there). Part G uses about 1,100 px.
The test events
Fall Classic (Lakeshore Lightning, yellow, /stage1-lakeshore-lightning/fall-classic): today’s games, one semifinal live. Claude changes that one game between live, unofficial, final, upcoming, cancelled and time not set. Stage 5 teams (Metro Sports): stage5-live, stage5-between, stage5-champion, stage5-empty, each a different state of a team. Cedar Valley (before the event, something open) and Pinecrest (crowned, nothing open) for the host card. Spring Invitational (Hamilton-Wentworth) for Register. Stage 6 sample event for News.
The layout check
Claude ran it on a production build of this code before the walk, on the 25 public tournament screens at phone, tablet and desk widths. 17 were measured. They are clean apart from two known things: the demo tour bar’s own small buttons on the Overview, and the nine short links on News and Register at tablet width. 8 could not be measured: six wait on test events that have aged (a live game, a live playoff, the Stage 4 events) or on the old name “The bracket”, and two more (a seeded bracket and a bracket-only Schedule) were added to that list this time. So the live game, the live playoff card and the bracket were not measured; this walk covers them by eye (parts B, C and the bracket link).
Leaves behind
Nothing, once Part Z is done: the game goes back to live, the sample post comes off, the time comes back.
