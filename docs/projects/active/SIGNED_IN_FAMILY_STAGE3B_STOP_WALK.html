A second parent can stop the sign-up emails

Written 2026-11-06 for Stage 3b (built, not yet committed). One purpose: a person whose email was typed on someone else’s sign-up presses one link, the club’s sign-up emails to them stop for good, the registrar can see it, and nobody else’s mail changes.

What this walk is for

Before this build, a second parent’s only way off was to write to the club. Now every email the second parent gets has a quiet line at the bottom, A parent added your email to this sign-up. Don’t want these? with a Stop these emails link. The link opens a page with one button, and no sign-in. Pressing it takes the address off every sign-up the club has, for every season, and the club can no longer add it again. Nobody is emailed about it. The registrar’s record window then reads Stopped by the address owner with the date, and both the sign-up form and the registrar’s windows refuse that address in words. The first parent’s emails are unchanged.

It passes when

  • A second parent’s confirmation and a later email (Approve) both carry the quiet line and the Stop link; the first parent’s emails carry neither.
  • Opening the link changes nothing; pressing the button stops the address on every sign-up of the club, and a second press shows the same finished page.
  • The registrar sees “Stopped by the address owner, {date}” on every sign-up that held the address, still sees the address on a sign-up that was not stopped, and cannot turn it back on.
  • The family form and both registrar windows refuse the stopped address in words, with capitals and spaces ignored, and create nothing.
  • After the stop, no later email reaches that address; a different address can still be added.
  • A link with a changed token says so and changes nothing.

Not in this walk

  • “Email families” has its own Unsubscribe link and is not part of this stop.
  • The same mailbox under a +tag. The stop is for the exact address; you+st1b@ and you+st1x@ are different addresses. Recorded as an open flag in the legal note, not a defect to find here.
  • A club-customised confirmation email (cannot carry the line; the second parent always gets the built-in one).
  • Production. Migration 448 is on dev only; it goes to prod before the promote that ships this.

Before you start

Dev server
This build adds a new page, a new route and a database change. Stop the dev server, delete .next, run npm run dev and wait for “Ready”. Part S shows whether it is the new build.
Email
RESEND_API_KEY and UNSUBSCRIBE_SECRET are set in .env.local and NEXT_PUBLIC_APP_URL=http://localhost:3000. Without the secret no Stop link is drawn at all (Part B tells you); without the key every “inbox” step fails.
Your inboxes
Use your own address with plus tags (call it you@gmail.com): you+st1@ is the first parent of Walk Alpha, you+st1b@ is the second parent on both Alpha and Beta (the one we stop), you+st2@ is Beta’s first parent, you+st3@ and you+st3b@ are Walk Gamma’s two parents (Gamma is the control: its second parent is never stopped), you+st1c@ is the “different address” in Part G. The dev .local addresses cannot receive mail.
Reruns
A child is refused as a duplicate with the same first email, and an address is limited to 8 sign-up attempts an hour. On a second run use new tags (+su1 …). A stopped address stays stopped for the club until Claude removes the stop in Part Z, so a rerun with the same st1b would be refused.
Email not there?
Wait 2 minutes, then look in Resend › Emails and search the address.
When done
Part Z: tell Claude “stop walk done” and it removes the walk’s sign-ups and the stop.

Calls to make as you go
