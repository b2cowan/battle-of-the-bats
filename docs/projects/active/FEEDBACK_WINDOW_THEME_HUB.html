Your calls

Six asks

The new look itself is settled: you asked for it, and each portal’s window already exists. These six ride along. Each one can be dropped without affecting the rest.

A1 · Account page and public pages: the coach window, on your Warm / Dark setting

These pages have no window of their own. Only coaches see Send feedback on the account page.

Recommend: yes. The alternative is to design a third window for two low-traffic doors.

A2 · Drop “(optional)”, and put a plain asterisk on Description

This is your standing rule: mark the few required fields, never the many optional ones. Description is the only field Send waits for.

Recommend: yes.

A3 · Type becomes a dropdown: Bug, Feature request, General feedback

Your standing rule: a form field that chooses one value is a dropdown, never a row of buttons. The case against it: three visible buttons tell people they can suggest a feature as well as report a bug, and a dropdown hides that until it is opened.

Recommend: dropdown. The window’s title already says “feedback”, and the description’s hint changes with the type. “Feedback” alone as a type, inside “Send feedback”, says nothing, so the third option becomes “General feedback”.

A4 · Category: stop asking for it

Today’s list is Tournaments, Coaches, Registrations, Accounting, Billing, Other. It has no Rep teams, House league, Families or Schedules, so your screenshot guessed “Other” on the Rep teams page. People rarely change a guess, so the field mostly records a wrong guess.

Option 1 (recommended): remove it from the form. We already record the page the person was on, so the category is filled from it, and the list gains the club’s areas so your feedback inbox filter still works.
Option 2: keep the field and add the club’s areas to the list and to the guess.

Recommend: option 1. One less field, and the record is right more often.

A5 · After Send: close with a fading pill, or a thank-you window?

The portal ends every other send by closing the window and showing a pill that fades (screen 5, option 1). Today’s feedback window instead turns into a thank-you with a Done button (option 2). On a phone, option 2 is one sentence on an otherwise empty screen.

Recommend: option 1, the pill, reading “Feedback sent. Thank you.” It matches every other send and needs no tap. What it gives up is today’s second sentence, “Our team reviews every submission.”

A6 · Ask before throwing typed words away

Today Cancel, × or a tap outside silently wipes a description someone has written. The admin’s Message a family asks first: “Close without sending? What you typed won’t be kept.” with Keep writing and Discard. In the coaches portal, a tap outside a window closes it with nothing asked.

Recommend: yes, in both portals. Someone writing feedback is often already frustrated, and losing what they wrote makes it worse. With nothing typed, the window closes at once as it does today.

Found on the way, not in this work (F06). The club admin’s forms paint the required asterisk red, against your rule that it is plain (red means something went wrong). The feedback window uses the plain one. Fixing every club form is a separate call; it is reported here so it does not get lost.

What the design review changed

The review read each drawing against the portal’s written rules and the real window code. Its changes are proposals until you rule on the drawings.

Changed in the drawings

  1. Today redrawn at true size. The first round copied your screenshot, which was taken at 125% zoom, so the old window looked about a quarter bigger than it is. It is 480px wide, with 12px title type.
  2. Phone titles at 16px. Both portals keep the title size on a phone; the first round enlarged it.
  3. Phone side margins per portal: 20px in the admin, about 14px in the coaches portal.
  4. Coach phone fields and buttons at their real size (35px and 34px). A 44px floor for coach windows is the portal-wide tap-floor ruling already owed; this window follows whatever that ruling decides.
  5. Three missing states added: as opened (empty, Send faded), could not send, and closing with words typed. Everyone sees the empty state first, and the first round drew only the typed one.
  6. After Send gained the portal’s own ending (close and a fading pill) beside the thank-you window. That became ask A5, and the closing question became ask A6.

  • The scrims match the code: lighter and warm in the admin, darker in the coaches portal.

Product-manager brief

Feedback window: wear the portal that opens it

What changes

“Send feedback” opens a window that looks like every other window in the place you opened it from. In the admin it is the admin’s form window; in the coaches portal it is the coach window. Both follow your Warm / Dark choice. On a phone it fills the screen like any other form, with ← to leave. Coaches opening it from their account page or the public pages get the coach window in their own theme.

Riding along, if the asks are accepted:

  • The type becomes a dropdown.
  • The category stops being asked; it is filled from the page.
  • “(optional)” goes, and Description is marked as the one required field.
  • Send closes the window with a fading pill.
  • Words already typed are not thrown away without asking.

Why it matters

It is the last window still wearing the old terminal look, and it is the window people open when something already feels wrong. In Warm, a dark mono card over a light page reads as a different product at exactly that moment. Today a stray tap outside the window also wipes what they wrote. The category guess is wrong on every club screen, because the list predates the club.

Customer impact

Everyone signed in who sends feedback: club and tournament admins, paid and free coaches. Nothing else on any screen changes. Your feedback inbox keeps working; if A4 is accepted it gets a more accurate category.

Priority

Small, and not blocking anything. It fits beside the Club release’s polish.

Success criteria

  • Open Send feedback from every door, in Warm and in Dark, on a computer and a phone: it always matches the screen behind it. No mono capitals, no dark card on a Warm page, no white text on a white card.
  • Typed words are never lost to a stray tap.
  • A build check fails if the window is ever opened outside the portal’s look again.
Full assessment

Feedback window: implementation plan

Problem

One shared window serves every Send feedback door. It attaches itself to the bare page instead of inside the portal, and its fields hard-code the old dark colours and the mono face. The admin already restyles plain windows that sit inside its frame, and the admin’s other floating pieces (the bottom sheet, the chat panels) were moved inside it. This window was missed, so it shows the base terminal look on every surface and in both themes.

Findings

F01 — Opens outside the portal. The window is attached to the bare page, so no portal’s look reaches it.

F02 — Old type. Mono capitals for the title, labels and buttons, square corners, a boxed ×.

F03 — A row of buttons for a one-value field. Against the standing dropdown rule (A3).

F04 — “(optional)” on Title. Against the required-marker rule (A2).

F05 — The category list predates the club. No Rep teams, House league, Families or Schedules; club screens guess “Other” (A4).

F06 — The club kit’s required asterisk is red. Out of scope; reported for a separate call.

F07 — Typed words are wiped silently. Cancel, × and a tap outside throw the description away with nothing asked (A6).

F08 — The admin and the coaches portal have two window looks. Label case, field fill, width, spacing, scrim and border all differ (both titles are the same Barlow face), and no ruling chose it: the one ruling that joined the two windows (2026-09-27) unified how they behave, not how they look. Raised by the owner on this hub 2026-10-18; it is now its own project, One window, which covers the tournament admin too. This window is built on each portal’s own window, so it follows that project’s decision without further work.

Scope

  • The window’s look on every door, in Warm and Dark, computer and phone, in all four states.
  • The ending after Send (A5).
  • The content asks A2–A4 and the closing ask A6, as ruled.
  • A build guard so the window cannot drift out of the portal again.
Out of scope. Making the admin and coach windows one look (F08, its own project). A 44px floor for coach windows (the owed portal-wide tap-floor ruling). The other global windows: the three tournament windows already get the admin restyle, and the shared “are you sure” window is already skinned for coaches. The club kit’s red asterisk (F06). The admin’s faint field edges in Dark. Your feedback inbox screen.

Approach

  1. Wear the host’s window. Opened in the admin, the window is built on the admin form window (the one Message a family uses), inside the admin’s frame. Opened in the coaches portal, it is built on the portal’s form window, placed inside the portal’s themed root (the expense panel already does this). On the account page and public pages, it takes the coach window coloured from the person’s Warm / Dark setting. Build note: the hosts can tell the window which it is, or it can read the admin frame’s context. Check whether any guard limits the admin window to admin files before choosing.
  2. Fields on the portal’s own field styles, with no hard-coded white or mono anywhere in the window’s stylesheet. This prevents the white-on-white trap: moving only the frame would leave white text on a white Warm card. The required asterisk is written plainly, not with the club kit’s red marker (F06).
  3. The asks, as ruled. If A4 is accepted, the server fills the category from the page using the existing route guess, extended with the club’s areas. Build note: confirm whether the stored category has a database check before adding values. If A5 is accepted, Send closes the window and shows the portal’s fading pill. If A6 is accepted, the window copies Message a family’s closing ask.
  4. A guard: the window never attaches to the bare page outside a themed root, and its stylesheet carries no literal colours or data face.
  5. Tidy: remove the unused launcher button, and update the two nav guards that read it. Update the admin layer guard’s row for this window to the layer of the shell it now uses.

Verification

Focused checks on the changed files, and a typecheck, because a shared component changes. Then an owner walk of every door in the census, Warm and Dark, computer and phone, sent once from each portal.

Rollout

No database change is expected (see the A4 build note). No help article describes the form’s fields, only where to find it, so the help guides do not change. No demo tour step points at this window.
