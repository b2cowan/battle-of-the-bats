Setup check — is the dev site really wired?

Written 2026-10-28. One purpose: prove the dev site, Stripe's sandbox and the email service are really connected to each other before any Stripe walk spends your time. Nothing is paid and nothing that matters is changed.

What this walk is for

Every Stripe walk after this one assumes five things are true: the site talks to the sandbox Stripe account you are looking at, Stripe's three webhook destinations reach the site, a real email leaves the site and arrives, the "buy" button opens Stripe's real hosted page (not the fake shortcut), and UAT Rep Club can take payments on a tournament that exists. This walk shows each one on screen, so a walk that fails later fails for a reason in the product, not in a setting.

It ends with one table: tick the walks that are unblocked, and paste that back.

It passes when
  • The Plans table shows Stripe test price ids set for every paid plan, and you know which plans are Live and which are still Early access.
  • A real email from the site arrives in your inbox from FieldLogicHQ <noreply@fieldlogichq.ca> and shows as Delivered in Resend.
  • The coach "Continue to checkout" button opens Stripe's own page in test mode, and the customer the site just created is in your Stripe sandbox.
  • All three Stripe webhook destinations show a 200 (or, for the account-events destination, a response that proves it reached the site).
  • UAT Rep Club's Payouts card reads Taking payments with the Test mode chip, and the walk-only tournament's public page is open for registration with a full Walk 15U.

Before you begin

Part D needs the walk-only tournament Stripe Walk Invitational to exist. It is created by a seed script that whoever prepared this walk runs once (scripts/seed-stripe-walk-tournament.mjs with your inbox address). Part D opens by showing you whether it is there.

Webhooks (Stripe dashboard › Workbench › Webhooks)
  • Billing — https://dev.fieldlogichq.ca/api/billing/webhook (plans, subscriptions, invoices)
  • Dev: club payments — https://dev.fieldlogichq.ca/api/payments/connect-webhook (a club's checkouts, refunds, disputes)
  • Dev: club account events — https://dev.fieldlogichq.ca/api/payments/connect-account-events (a club's Stripe account itself)

Each destination has an Event deliveries tab. What its numbers mean for this site: 200 = arrived and understood; 400 = the signing secret saved on the site is not this destination's; 503 = the site has no signing secret saved at all; 404 = wrong address, or the dev site has not been built with that page; 500 = the site got it and failed while handling it.

Test cards (for the walks after this one)
  • Approved: 4242 4242 4242 4242
  • Declined: 4000 0000 0000 0002
  • 3-D Secure (asks you to confirm): 4000 0025 0000 3155
  • Attaches fine but fails when charged later: 4000 0000 0000 0341

Any future expiry date, any 3-digit security code, any postal code. This walk never asks for a card.

Email log

Every message the site sends appears in the Resend dashboard › Emails (recipient, subject, Delivered or Bounced). When an email does not reach your inbox in about 2 minutes, look there first. Your inbox address for this walk is your real one with +setupcheck added before the @ (for example yourname+setupcheck@gmail.com); it lands in your normal inbox.

If a check fails, what it points at
  • Part A (plans and prices): Test below 2/2 means a Stripe test price id is missing — set it in Platform admin › Plans & pricing (a price change goes through a change request). A plan reading Early access is a setting in the same screen. A readiness line named after a setting (webhook secret, application address) is an Amplify variable on the dev branch.
  • Part B (email and the Stripe page): no email, or the wrong sender — RESEND_API_KEY and RESEND_FROM on the dev branch (the sender must be FieldLogicHQ <noreply@fieldlogichq.ca>; if RESEND_FROM is empty the site sends from Resend's test address) and the domain's status in Resend. No Stripe page, or no customer in your sandbox — STRIPE_SECRET_KEY (must be the sandbox's sk_test_ key) and NEXT_PUBLIC_APP_URL (must be exactly https://dev.fieldlogichq.ca, no slash at the end). "Create team" instead of "Continue to checkout" means the free-offer date was overridden on the dev branch.
  • Part C (webhooks): a 400 or 503 is the destination's signing secret: STRIPE_WEBHOOK_SECRET (Billing), STRIPE_CONNECT_WEBHOOK_SECRET (club payments), STRIPE_CONNECT_ACCOUNT_WEBHOOK_SECRET (club account events). Amplify copies them in at build time, so a changed variable needs a fresh dev build before it counts.
  • Part D (Payouts and the tournament): no Payouts card, or Taking payments missing — ONLINE_PAYMENTS_ENABLED must be exactly true on the dev branch (with a sandbox key), and UAT Rep Club must still be connected (the club fixture script rebuilds it). Page not found for the tournament — the seed script has not been run.
