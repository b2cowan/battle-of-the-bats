The family’s link, end to end

Written 2026-11-01 for Stage 1, Session 2 (Parts 5–8). One purpose; sign it off on its own. Session 1’s page, “Email me my link” and the ended screens are read again here only where this session’s changes pass through them.

What this walk is for

A family’s one link opens “Your sign-up”, which names each child by first name and now hides most of the parent’s email. The club can stop that link and send a new one with Send a new link. That stops it for every brother and sister on the sign-up at once, and the new one opens for all of them. This walk follows one family, the Walkfams (Maya and Leo, one sign-up), through the page, the club’s new row, the old link stopping and the new one opening.

It passes when

  • The family page shows Maya and Leo by first name only, and the parent’s address only as p•••@example.invalid, wherever it appears.
  • Stripe’s checkout page names each child by first name.
  • The registration’s “What you can do” has Send a new link, whose hint names Maya and Leo. Its confirm, toast and history line read as drawn.
  • After the reset, BOTH children’s old links say “This link no longer works”, and both new links open the page.
  • A registrar sees the row too (it is not only for the people who handle money).

Not in this walk

  • The emails. Dev sends no email, so the new “Your sign-up” button (and where it no longer appears: a paid family’s placement email, a fully paid receipt) cannot be read here. The unit tests pin each email against the drawing’s tab 5 table. Read them on the first production sends.
  • The unsubscribe secret. Nothing changes on screen while the secret is set (it is, on dev). Your production step is listed in the hand-off.
  • Paying. Part B opens Stripe’s page only to read its lines, and leaves without paying.
