What this walk is for

The Accountant package (the ZIP you hand your accountant) now carries the GST/HST return as well: gst-hst-worksheet.csv (lines 101 to 109 for the package's dates), gst-hst-credits.csv (every expense behind line 106 and what happened to its credit) and, when you marked a return as filed inside those dates, gst-hst-as-filed.csv (every filing, every revision, exactly as saved). The package's one invoice file is unchanged.

It also settles one thing left open from the last walk (§488): whether marking October 2026 as filed again, with a reason, really saves. Dev holds one October filing, not the two part D described. Code, the real worksheet and the database all accept the second filing when I run them here; the one thing I cannot run is your signed-in browser. So parts A and C use the browser's Network tab, and a failed save will tell us exactly why.

It passes when the three files read the same as the return screen, the filed return in the package never moves when an expense changes, a credit added after filing is explained in the credits file, and the second filing saves (or the Network tab shows why it did not).

Not in this walk: the invoice file (walked in §493), the return screen itself, anything on a club or coach screen, and the backup drill (a command, not a screen; see the last part).

Before you start: this walk writes once, and a filing can't be deleted

  • Part C marks October 2026 as filed a second time (revision 2). The app has no way to remove a filing. Part F asks whether to clear the walk's rows from dev afterwards (October's two filings and the "Walk test supplier" expense).
  • Do the parts in order. The credit shows as "carried to a later return" only until October is marked again; part C is what moves it.
  • Open the browser's developer tools (F12, then the Network tab) before part C and leave it open.
  • Each package step downloads a ZIP. Unzip it somewhere and open the files in a spreadsheet or a text editor.
