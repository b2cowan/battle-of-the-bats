A code after the password

Anyone can now turn on two-step sign-in, and FieldLogicHQ staff must. After the password, the same sign-in page asks for the 6-digit code from an authenticator app. Setting it up is three screens: scan, save ten backup codes, done. A backup code gets you in if the phone is lost. Four walks, one purpose each. About 30 minutes, and you need an authenticator app on your phone.

Not in this walk: the Account page's Sign-in & security section and "Lost your phone?" (Part 2), the club's two switches and their 14 days (Part 3), and the Members column, Overview notices and emails (Part 4). Until Part 2, the set-up page is reached by its address or at sign-in.

Before you start

  • Install an authenticator app on your phone if you don't have one: Google Authenticator, Microsoft Authenticator, 1Password, or the Passwords app on an iPhone.
  • Walk the parts in order, 1 to 4. Walk 3 signs in to the account walk 2 sets up. Each walk opens with a stop check.
  • After the walk, support@dev.local and coach@dev.local keep two-step on, and every sign-in to them asks for a code from your phone. Tell me if you want them reset.
  • The drawings these screens were built to: tabs 2, 3 and 9.

Already proved by tests and my own pass (don't re-do these)

  • A password alone opens nothing for someone with two-step on. Every server route and page refuses that session (25 build checks, and 18 deliberate breaks each caught), and so does the database itself for the 15 tables a signed-in account can reach directly.
  • Every place that signs a person in (twelve of them, not five) hands off to the one code step.
  • On dev, with throwaway accounts: an owner of a club that requires it, with it off, is sent to set-up and refused by the club's routes, while their other places stay open. Inside the 14 days, and in a test organization, they are let in. Staff with it off are sent to set-up; with it on and the code typed, they are in.
  • Refreshing a session keeps the code; setting it up signs the account out on every other device; replacing a lost phone after a backup code keeps you signed in, and two-step stays on for the account until the new phone is set up (a stolen password is still refused mid-way).
  • Staff "sign in again" (bulk changes, a Production price) now asks for the code instead of the password.
  • Each new demo visit clears any authenticator off the shared demo account.

Your time goes on judgment: do the screens read as the next step after the password, is the code easy to type on a phone, and does each screen say only what the person needs?
