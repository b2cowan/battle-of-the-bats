The defect underneath the inconsistency

A global table rule uppercases every row heading into the condensed display face. The By-period grid explicitly cancels it — its code carries a note about a coach seeing “MCTAVISH ARENA — WINTER BLOCK” shouted back. The Months grid never did, so every line a coach typed, its closing total, and the whole cash-flow strip render in a typeface used nowhere else for a coach's own words. Measured, not eyeballed: text-transform: uppercase, Barlow Condensed, on Winter dome block, Diamond permits and Spring classic entry.

Proposed. Identical chrome to the panel above. Line names read as the coach typed them. The cash-flow strip stays visibly a different KIND of row — separated by a rule and set in quieter ink — rather than by being the loudest thing on the screen. One minus sign.

What stays different, on purpose

The year band vs. the “’26” suffix. A season plan spans one or two years and groups its columns under a band; a twelve-month view labels every column. Different data, not drift.

The chevron. It appears only where categories actually collapse (Months). An affordance for a behaviour, not decoration — a chevron that does nothing is worse than none. If you want By period to collapse too, say so and it becomes one more line rather than a redesign.

The cash-flow strip belongs to Months alone. Projecting a running balance needs dated columns; the plan's period view has an Unscheduled column precisely because some of it has no date.

What this costs

Three edits in the shared grid treatment and one in the number formatter. No behaviour changes, no controls move, no data changes. The line-name fix is the same reset the By-period grid already carries, moved somewhere both can use it — so the next money grid inherits it instead of re-discovering the shouting.
