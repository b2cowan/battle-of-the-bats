What holds

The rules this drawing follows

These are drawn constraints, not new interpretations of settled product decisions.

The surface can change while the event shell stays distinct. Direction A keeps the tournament's event title, date/status, event pages, global phone bar, game details, and data order. It changes the ground, typography, role mapping, and first-screen repetition.

Warm public face

Paper #F8F4ED, white cards, ink #241E15, soft ink #4A4235, dim #615A54, olive #57651E. Barlow Condensed 700 headlines and Inter text. Google Fonts only. Lime #D9F99D is never text on paper.

Binding instruction · public-face palette and type

Organizer identity with safe contrast

The roles from the club implementation: fill for a band/button; on-fill for text; ink at 4.5:1 on the light ground; edge at 3:1; accent for decoration only. No tints. A pale fill switches to dark text and dark ink/edge.

Club Tier Stage 4b-1 Ask 8 · lib/club-colour-roles.ts

Keep the event's family content

No permanent content is proposed to go. Collapse or reorder less frequent information. Standings remains a table on a phone, with Team held left and PTS held right.

2026-06-01 public tournament mobile remediation · 2026-07-20 nav unification

One home, two states

Before an event, a compact event introduction and open registration can lead. During the event, the first content is today's live or next game. A page title does not repeat the event header.

2026-06-01 home-state ruling · 2026-07-14 G3 / G4

Tap targets and controls

Primary controls meet the 44px target. The stage switch is one track. A phone's secondary action is its symbol alone. The drawings use clickable details for expandable content and a click-open live-status explanation.

Binding rules in the review prompt · shared schedule controls

Clock labels and examples

Times use lowercase periods, for example 4:00 p.m. The stress fixtures are explicitly labelled test data; no test names or numbers are presented as tournament facts.

Owner spelling ruling · 8:00 a.m. style

Club host and standalone host

A club host gets a link only if its public page exists. A standalone event works by itself. A free event has no host logo; it never borrows a club mark.

TH-1 organizer identity · tournament branding entitlement

Recommended

Direction A · warm event venue

Keep event navigation and data jobs. Share the public visual language, with organizer colours in safe roles.

Why this directionIt respects organizer identity without requiring a club site. It keeps the event shell and avoids a second club-style nav. A big dark hero is not needed to distinguish the tournament; the event name, date, brand mark, and game data do that.

Decision panel

Owner questions

Ranked by how much the answer changes the proposal.

The framing to decideKeep a separate event shell and organizer identity; decide whether the shell shares the warm ground and colour-role method. Copying the full club frame is not required for continuity.

First · warm ground for all public tournaments?

Approve Direction A: warm paper for club-run and standalone events, organizer colour through safe roles, free standalone events without a host logo. This changes every public tournament screen and supersedes the dark “venue” surface rule.

Recommended · preserve the structural carve-out, retire the visual carve-out.

Second · tournament-owned sponsors, on every plan?

Approve a separate event sponsor list and show configured sponsors even for free tournaments. The club's list remains on the club site. This needs new editor and data work.

Recommended · no invented tiers, no automatic copying.

Third · host-club card near the end of Overview?

Approve “Run by [club] / Visit the club” only if a real public club page exists. No card for a standalone organizer or a club whose public page is unavailable.

Recommended · useful advertising after game data.

Fourth · focused payment-only shell?

Approve suppression of event tabs, desktop rail, ticker, and growth/follow chrome around emailed payment links. Keep a return-to-tournament door.

Recommended · pending valid-token visual confirmation.
