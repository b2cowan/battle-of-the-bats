## Goal

A team's **real platform tournament games** stop being read-only chips and become first-class games on the team calendar: attendance, lineups, the season record, Insights and Wrapped all work on them exactly the way they work on a league game — while the **time, opponent, venue, score and cancellation stay true to the organizer's schedule**, automatically, when the tournament side changes. And **Attendance gets a real front door** in both navs instead of hiding behind a secondary button that disappears in one roster view.

## Ground truth (verified by direct code read, 2026-07-29 — treat as verified, do not re-derive)

### Why tournament games have no tools — confirmed exactly as the review claimed

- **Attendance and lineups both hang off `rep_team_events.id`.** `rep_team_event_attendance.event_id` FK → `rep_team_events.id` with `UNIQUE(event_id, player_id)`; `rep_team_lineups.event_id` FK → `rep_team_events.id` with `UNIQUE(event_id)`; `rep_team_lineup_entries` hangs off the lineup. There is no second key anywhere in that family.
- **A real platform tournament game is a tournament-side `games` row** reached through the team's registration (`teams.id` = the registration id; `games.home_team_id`/`away_team_id` point at registrations). It has **no `rep_team_events` row**, so there is nothing for attendance or a lineup to attach to. Confirmed.
- **How the Schedule renders them today:** `app/[orgSlug]/coaches/teams/[teamId]/schedule/page.tsx` fetches `/api/coaches/[orgSlug]/teams/[teamId]/tournament-games` in parallel with `/events`, and renders each one through `TournamentGameChip` (line 451) — a gold-accented, **read-only** chip that either links to the public game page or is inert. Its own comment states it: *"games flow through none of the editor / attendance / lineup / save paths."* They appear in list, week and month views and in a trailing **"To be scheduled"** group for undated (unresolved-bracket) games.
- **What identity/link data each chip carries** (`CoachScheduleTournamentGame`, lib/basic-coach-teams.ts:1195): `id` (the real `games.id`), `startsAt` (ISO local, null when undated), `gameDate`, `opponentName`, `location`, `myScore`/`oppScore`, `status`, a derived `phase` (`live|final|scheduled`), a derived `result` (only for finalized `completed|forfeit`), `tournamentName`, and `href` (public game page, only for `active|completed` tournaments). ⚠ **Security invariant recorded in that file: this shape carries NO fee/money field** — which is why the `/tournament-games` route skips the money-redaction gate. Anything added to it must keep that true.
- **The honest-reveal rules already applied** by `loadAcceptedTournamentGameRows`: only `accepted` registrations, only **published** divisions (`divisions.schedule_visibility = 'published'`), opponent names resolve only from accepted teams (else the placeholder, else "TBD"), "live" = a submitted score dated today in **tournament time** (`tournamentNow()`, never raw UTC). Batch 4 inherits these unchanged — they are the reveal contract.
- ⚠ **The `/tournament-games` route only reads the WORKSPACE bridge** (`team_workspaces.basic_coach_team_id`), not the mig-196 admin-link bridge that Batch 1 taught the *tournament-history* route to read via `getMergedTournamentHistoryForRepTeam`. So an **org-created rep team with an admin-linked registration sees its tournament on the Tournaments page but NOT its games on the Schedule** — a live inconsistency Batch 1 half-fixed. Batch 4 closes it (Phase 1.4).

### The architectural fork — the answer is already sitting in the code

**Every downstream tool already accepts `event_type = 'tournament_game'`.** Verified constant by constant:

| Consumer | Constant | Includes `tournament_game`? |
|---|---|---|
| Lineups list + "needs lineup" filter | `GAME_EVENT_TYPES` (lineups/page.tsx:16) | **yes** |
| Lineup save route (allowed types) | `GAME_EVENT_TYPES` (events/[eventId]/lineup/route.ts:21) | **yes** |
| Attendance season report / reliability | `ATTENDANCE_GAME_TYPES` (lib/db.ts:5180) | **yes** |
| Canonical season record + Wrapped | `WRAPPED_RECORD_EVENT_TYPES` (lib/season-wrapped.ts:20) | **yes** |
| Overview phase + anchors + snapshot tiles | `GAME_EVENT_TYPES` (page.tsx:25, coach-rep-phase.ts:12) | **yes** |
| Admin past-year record | imports `WRAPPED_RECORD_EVENT_TYPES` | **yes** |

- **Option A (mirror)** therefore needs **one column + one sync path**, and every tool listed above works with **zero changes**. The mirroring precedent exists: `rep_team_events.source_basic_event_id` (mig 143) — a nullable, **non-FK** provenance tag with a partial-unique index `(program_year_id, source_basic_event_id) WHERE NOT NULL`, written only by the free→premium upgrade path. ⚠ Read the difference honestly: mig 143 is a **one-shot copy**, not a live sync. Batch 4 needs the sync; the column shape is the precedent, the freshness is new work.
- **Option B (polymorphy)** would add a second nullable key to `rep_team_event_attendance` **and** `rep_team_lineups` (both of which have single-column UNIQUE constraints keyed on `event_id`, so both need new partial-unique indexes and both writers need branch logic), then thread the OR-branch through the six consumers above plus `getRepTeamLineupSetEventIds`, `getRepTeamLineupAttendanceMismatchEventIds`, `computeSeasonLineupAnalytics`, the playing-time report, and the schedule slide-over. **Two migrations, ~12 touch points, every existing query gains a branch that can silently miss one arm.** Recommended against (D1).

### Where the mirror gets its scope

- `rep_program_years` has **no start/end dates** — only `name`, `year` (integer), `status`, `created_at`. So "which season does this tournament game belong to" cannot be answered from a season window.
- `getActiveRepProgramYear` resolves `draft|active`, newest `created_at` wins. **A closed season can never be a sync target by construction** — which is exactly the Batch 3 contract ("no attendance/lineup writes against a closed season's games") satisfied for free.
- Proposed season floor (D2): a game mirrors into the current season only when its date is **on/after the season's start marker** = the earlier of the program year's `created_at` date and the earliest existing event already in that year. A game played before this season began belongs to the one that closed.

### Duplicate risk — the thing the review did not anticipate

Coaches working around this gap **hand-enter their tournament games today** (`event_type='tournament_game'` is fully supported in the Add Event form, and `external_tournament` parents can spawn child game slots). The moment the mirror lands, those teams see **two rows for the same game — and both count toward the season record**, which now visibly changes their W-L. This must be handled at launch, not discovered at QA (Phase 3.1).

### Attendance's missing nav home (the P1)

- The season report lives at `app/[orgSlug]/coaches/teams/[teamId]/attendance/page.tsx` (154 lines, read-only, games/practices split per player, "attended / known" with no-reply excluded).
- **Its only door is a secondary button on the Roster page** (roster/page.tsx:504) — which disappears in the depth-chart view. It is in **neither** nav. Confirmed independently by two reviewers (f2-6, f6-0 ×2, f8-2).
- **Attendance is RECORDED** in the Schedule's event slide-over (`?event={id}&tab=attendance`), auto-saving ~0.7s after the last tap, with a two-way lineup↔attendance reconciliation banner. The report never links to it and it never links to the report.
- Nav plumbing: `lib/coach-nav-visibility.ts` `isCoachNavItemVisible(caps, label)` is the shared gate for both `CoachesSidebar` and `CoachesBottomNav`; `CLOSED_TEAM_NAV_ITEMS` is the closed-season door list. A new door added to the gate + the sidebar's `TEAM_NAV_GROUPS` reaches both navs. `caps.attendance` already exists (assistant default: **on**).

### The game-day card downgrade (f2-3), for the bundling call

Confirmed verbatim in `teams/[teamId]/page.tsx`: the **`in_season` anchor** (3 days out) offers `Build lineup` **and** `Take attendance` deep links; the **`game_day` anchor** (the actual day) offers one generic `Open game day → /schedule`. It already renders attendance headcount and lineup-ready state — the downgrade is purely the action row. **Fixing it is ~6 lines on a surface this batch already reworks** (a mirrored tournament game will now be able to *be* the game-day anchor).

### Capability gates — confirmed, not assumed

Because mirrored games are ordinary `rep_team_events`, they route through the **same** endpoints and therefore the **same** gates: `/events` and the slide-over require `capabilities.schedule`; attendance writes require `capabilities.attendance`; lineups require `capabilities.lineups`. Assistant defaults have all three **on**. **No new capability, no new gate, no assumption** (answers the build prompt's open question).

## Phases

### Phase 1 — Tournament games become real games (P0 #2)

- [ ] **1.1 Migration `207_rep_event_tournament_game_source.sql`** — `rep_team_events` gains `source_tournament_game_id uuid` (nullable, **no FK** — a loose provenance tag exactly like `source_basic_event_id`, so an organizer deleting a game can never cascade-destroy a coach's attendance; our sync decides what happens) + partial-unique index `(program_year_id, source_tournament_game_id) WHERE source_tournament_game_id IS NOT NULL` (one mirror per game per season, idempotent by construction). Dictionary entry + `npm run refresh:snapshots` in the same commit; applied to dev **and** prod.
- [ ] **1.2 The mirror — `lib/rep-tournament-game-mirror.ts` (new, unit-tested).**
  `syncTournamentGameMirror({ repTeamId, programYearId, orgId, seasonFloor })`:
  - Source = `getMergedTournamentHistoryForRepTeam(repTeamId)` → `getRegistrationGamesForTeam(history)` — **both bridges**, all existing reveal rules inherited (1.4).
  - **Only dated games mirror.** `rep_team_events.starts_at` is NOT NULL, and an unresolved bracket slot has no date. Undated games keep today's read-only chip in the "To be scheduled" group and mirror automatically the moment the bracket resolves.
  - **Season floor** (D2) drops games dated before this season began.
  - Diff against existing mirror rows for the year:
    - **new** → insert (`event_type: 'tournament_game'`, `name` = tournament name, `opponent`, `home_away`, `starts_at`, `location`, scores/`result` when final, `status`).
    - **changed** → update **organizer-owned fields only** (see 1.3).
    - **gone from source** → **re-point first** (1.10), then, if no replacement is recognisable: **delete when the row carries no coach work** (no attendance rows, no lineup, no coach-owned field set, no tags); otherwise **`status = 'cancelled'`** and keep it. *The mirror never destroys a coach's work — and never leaves a phantom behind when there is none.*
  - Never touches a row whose `source_tournament_game_id` is NULL (a coach's own event is untouchable).
  - Pure diff logic split out and unit-tested (`tests/unit/tournament-game-mirror.test.ts`) — the reconcile decision table is the part that must not regress.
- [ ] **1.3 The field ownership contract** (binding; enforced server-side, reflected in the UI):
  | Organizer-owned — overwritten on every sync, read-only to the coach | Coach-owned — never touched by the sync |
  |---|---|
  | `starts_at`, `location`, `opponent`, `home_away`, `name`, `team_score`, `opponent_score`, `result`, `status` | `arrival_time`, `uniform`, `field_number`, `description` (notes), `resources` (links), tags, attendance, lineup |
  Arrival time and uniform are exactly what a coach adds to a tournament game, so the restricted edit form is genuinely useful rather than a stub.
- [ ] **1.4 `/tournament-games` reads BOTH bridges** — swap its workspace-only chain for `getMergedTournamentHistoryForRepTeam` (the lib Batch 1's `/simplify` already extracted for the sibling route), closing the org-rep-team inconsistency. ⚠ This file currently carries **one foreign hunk** from a concurrent session (`skipEntitlementCheck: !isTeamWorkspaceOrg(ctx.org)`) — keep it, do not revert it, and stage carefully.
- [ ] **1.5 Sync trigger — read-triggered self-heal at the one shared chokepoint.** `/api/coaches/[orgSlug]/teams/[teamId]/events` **GET** awaits `syncTournamentGameMirror` before reading events (per the `after()`-drops-on-Amplify rule: never fire-and-forget a side-write). That single route backs Schedule, Lineups and Overview, so every surface a coach can reach a game from is fresh at the moment they look. In-process debounce (`Map<programYearId, ts>`, 60s TTL) so a page-set costs one sync. **Failure is non-fatal** — logged, schedule still renders. Precedent: `resolveBasicCoachTeamIdForWorkspace` already self-heals on read.
- [ ] **1.6 Server-side write guards on mirrored rows** (defense in depth — the UI hides these, the API refuses them): `events/[eventId]` **PATCH** rejects (409, honest message) any organizer-owned field on a row with `source_tournament_game_id != null`; **DELETE** refuses outright ("This game comes from {tournament}. Ask the organizer to remove it."). Attendance and lineup routes are **untouched** — they are supposed to work.
- [ ] **1.10 Reschedule handling (owner-raised at approval; binding).**
  - **A built lineup survives a reschedule with zero coach action** — attendance and lineups key off the game, not its time slot, so a moved game carries them. Nothing to rebuild. *(No code needed for this; it is the property that makes the whole design work, and it must be verified by probe, not assumed.)*
  - **Re-point before cancelling.** Before treating a vanished source game as gone, the reconcile looks for a replacement among the source games **not yet mirrored**, matching on **(same tournament) + (same opponent registration) + (same calendar day)**. On a hit, the existing event's `source_tournament_game_id` is re-pointed at the new game id and the row updates in place — the coach's lineup, attendance, arrival time and notes all follow. Covers organizers who reschedule by delete-and-recreate and the admin **"delete tournament games"** bulk-regenerate path (`app/api/admin/games/route.ts` — a real wholesale re-identify). Ambiguity rule: if more than one candidate matches, **do not guess** — fall through to the cancel/delete rule.
  - **Tell the coach it moved.** The mirror records the previous `starts_at` when an organizer-owned time change lands (coach-owned data untouched) and the Schedule row shows a **Moved** chip + the game panel shows *"Moved from {day}, {time}"*. **Cleared once the coach opens the game** (per-event `localStorage`, the Batch 3 dismissal pattern — no schema, no new table). When the **calendar day** changed (not merely the clock), the line adds: *"Attendance was taken for the old time — worth re-checking."* **Attendance is never wiped.**
  - **Out of scope, deliberately:** push/email "your game moved" to the coach. `lib/schedule-change-notices.ts` + mig 205 (a **concurrent session's uncommitted** fan-side alert queue) already model exactly this event; duplicating it here would create a second sender. The coach-facing channel rides that work once it lands. **Do not couple to it in this batch.**
- [ ] **1.7 Schedule page: stop double-rendering.** Filter the `/tournament-games` list down to entries whose id is **not** already a `sourceTournamentGameId` among the loaded events. What remains = undated/TBD games only, still rendered as `TournamentGameChip`. Mirrored games render as ordinary `EventChip`s. **No provenance badge on the row** (owner call at approval): the amber left rail already colour-codes them and the tournament name is in the row text. Trailing chip space carries **state only** — lineup readiness, score/result, Moved, Removed.
- [ ] **1.8 Slide-over + edit form, restricted mode.** Opening a mirrored game gives the normal Attendance + Lineup tabs (the whole point), plus: a provenance line — *"From {Tournament} · organizer's schedule"* with a **View on the tournament page** link when the tournament is public; **Edit details** opens the sheet showing **only the coach-owned fields** (arrival time, uniform, field, notes, links, tags) with the organizer's time/opponent/venue shown as read-only context; **Delete** and **Cancel event** are not offered. Sheet contract unchanged (`CoachModalHeader`, `.modalFooter`, `useOverlayOpen`, `.formGrid` one column ≤640).
- [ ] **1.9 Types + reads.** `RepTeamEvent` gains `sourceTournamentGameId`; `getRepTeamEvents` / `getRepTeamEventById` select it. No other consumer changes — that is the entire point of Option A.

## Architectural decisions (proposed — ratify with the mockups)

- **Mirror, don't teach the tools polymorphy.** *Rationale:* every consumer already accepts `tournament_game`; Option A is one column and one sync path, Option B is two migrations and ~12 branch points where one arm can silently be missed. The mirror also makes tournament games work in tools nobody would have remembered to update (admin past-year record, Wrapped, playing-time).
- **The organizer owns the facts; the coach owns the preparation.** *Rationale:* a coach can never make their calendar disagree with the tournament they are playing in — but arrival time, uniform, notes, attendance and the lineup are theirs and are never overwritten by a sync.
- **The mirror never destroys a coach's work.** *Rationale:* a vanished source game becomes a cancelled event when attendance or a lineup exists, and disappears cleanly when nothing does. Deletion is the organizer's call about their schedule, never about the coach's record of it.
- **Sync on read at one chokepoint, awaited.** *Rationale:* the `/events` GET backs Schedule, Lineups and Overview, so freshness is guaranteed exactly where a coach looks; a cron sweep would add a moving part and the `after()`-drops-on-Amplify rule forbids fire-and-forget. Debounced so a page-set costs one sync.
- **Duplicates are surfaced, never resolved automatically.** *Rationale:* the coach's hand-entered game may carry attendance and a lineup; guessing wrong deletes real work. We name the collision and hand them a one-tap fix.
