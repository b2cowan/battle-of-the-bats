Which format, and when

The Export menu shipped with the file type on every row. Rendered, that turns three file types into twelve buttons — and the repeated part reads louder than the part that varies. Three ways to fix it, drawn at full size, with what each one costs.

Decided Option C, as a dialog. B was built, seen, and rejected too — so the file type left the menu entirely. The Export menu is now five names and nothing else; picking one opens a Save-As dialog naming each file type and what it is for. The lesson that took two rejected builds to land: anything drawn beside every item in a list is drawn as many times as the list is long. A and B both varied what sat on the row; only removing it worked. Built 13 Aug 2026.

The dataset names are the signal; the chips are wallpaper. Each row asks the same question again — and a coach who works in Excel answers it the same way every time. The original argument for chips-on-the-row was no second menu to open, which still stands: none of the three options below reintroduces a nested menu for the common case.

One thing that narrows the problem usefully: this menu never appears on a phone — the 2026-08-13 phone rule takes the whole row out at 640px, because spreadsheets are not phone work. So every option here is designed for a pointer, and hover is available as a tool.

The wrinkle, and how it resolves

Only two of the five make a PDF. With PDF selected, the other three have nothing to give — and a menu that silently does nothing when clicked is worse than a repeated chip.

This is the convention the tournament admin already uses — Excel on the primary click, everything else behind the overflow — and it is what the platform's own export standard already says in writing. Adopting it here makes two halves of the product agree.

ForThe quietest menu of the three. Matches an existing, written convention. One click, always.
AgainstCSV and PDF are hidden until you go looking — a coach may never learn a dues statement can be printed.
This was built and then rejected on sight — the second time in one session. On screen the "···" and the muted Excel tag still printed something beside all five names, and the owner's verdict was blunt: "doesn't look good." Two failures with the same shape are worth a rule. Anything you draw beside every item in a list is drawn as many times as the list is long — three tokens per row is twelve, one token per row is five, and it does not matter how quiet each is: together they out-shout the names they decorate. Options A and B both varied what went on the row. Only taking it off the row worked.
One thing from this attempt survived into the final build. Its flyout opened as a small floating panel beside the row — and the formats were invisible, because the menu is a measured, scrolling box and anything positioned outside it is clipped away. The rule that came out of it holds for the dialog too: anything this menu reveals has to live inside it, or somewhere else entirely.

C · Pick the data, then the format

The literal proposal: a clean list, and the format question asked after you have said what you want. Nothing is hidden and nothing repeats — it just costs a second click, every time.

The second panel earns something the others can't: room to name the file types in words — "printable statement" rather than "PDF". That is a genuine gain for a volunteer treasurer who does not think in file extensions.

ForSimplest to explain. Nothing hidden, nothing repeated. Room to describe each format in plain words.
AgainstTwo clicks for the thing coaches do most. Which datasets can be printed stays invisible until you have already committed to one — the question "what can I print?" now takes five openings to answer.
This is what shipped, built as a DIALOG rather than a second panel — the Save As / Export dialog every desktop application already has, which is the owner's own argument for it: nobody needs teaching. The second render above understates it. As built, each choice carries the file type, its extension, and a line saying what it is for — "Excel · best for working with the numbers", "PDF · a printable document you can share" — which is the thing a menu row could never have room for, and the reason a volunteer treasurer no longer has to know what an extension is.

Both costs above were accepted knowingly. The second click is real. And because the menu no longer shows which datasets make a PDF, the in-app Money guide now names them — when a screen stops answering a question, something else has to.

Seventeen counts the five dataset labels as targets too, since in every option the label is itself clickable. A and B are close. A is better at answering questions; B is quieter and matches an existing convention. C is the only one that costs a click on the common path.

The recommendation was A, narrowly — it answers "what can I print?" outright. It was overruled in favour of B, and the deciding argument is a good one: A buys that answer with a disabled row, a state this portal otherwise refuses to draw, and B brings the coach and admin sides onto one convention as a bonus. The cost accepted with B is that a coach may not discover a printable dues statement without opening a ··· — which the in-app Money guide now names explicitly, since the menu no longer does.

What none of them change

HoldsWhy it is not in scope
The five datasets What a coach can take out of Money is settled; this is only about how the file type is chosen.
The menu's place in the header Import ▾ / Export ▾ stay hub-wide and identical on all seven tabs — the 2026-08-13 ruling, not reopened.
Nothing on a phone The whole row leaves the header at 640px. Imports stay reachable through every empty state.
PDF is absent, never locked On a plan without PDF export the option does not render at all — in option A that means the format switch shows two choices, not three greyed to one.
Import ▾ Two datasets and a history line. It has no repetition problem and is not touched.
Scope, honestly stated. This is one panel inside a hub that is otherwise finished and ready for QA. Whichever option is chosen, it changes the contents of the Export menu and nothing else — no data, no permissions, no other screen.
