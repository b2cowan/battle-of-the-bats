Product-manager brief · proposed 2026-09-13

Exhibition: a third tournament style, no playoffs

What it does: When an organizer creates a tournament, the "Tournament style" step offers a third card beside Round robin + playoffs and Bracket only: Exhibition — games and standings, no playoff bracket. Picking it means the product stops promising a bracket everywhere it currently does: the schedule shows one list of games instead of a Round Robin / Playoffs switch, the dashboard never nudges "set up a playoff bracket", and the public page never shows a Playoffs toggle that reads "No playoff games yet". The moment the last score is in, the dashboard says Ready to finalize instead of waiting for the next day.

Why it matters

The product already sells this. The coaches marketing page promises "your round-robin, exhibition weekend, or local event"; the coach portal's own set-up card says "A quick round robin or exhibition weekend, set up from here"; the owner's delegation ruling describes the head coach's job as "run the exhibition weekend". The style picker is the only surface that contradicts all three, because both of its cards end in a bracket. Nothing blocks a coach from running a scrimmage day today, but four surfaces nag them about a bracket they will never build, and parents see a Playoffs stage that never comes.

Who benefits

Every organizer, on every plan — the style is a property of the tournament, so a club running a jamboree gets it too. It matters most to the standalone Premium coach, whose plan carries free-tier tournament tooling: no round-robin generator and no bracket generator. They type each scrimmage in by hand and were never going to touch a bracket, so every bracket nudge is noise aimed at exactly them. No role or plan gating changes.

What changes for the organizer

  • Creating a tournament — three style cards instead of two, in the setup wizard and in the org sign-up wizard. The new card reads Exhibition — Games and standings, no playoff bracket — for a scrimmage day or an exhibition weekend. On a phone the cards stack.
  • Event settings → Schedule Rules — the Tournament Format control gains an Exhibition segment, with its own one-line description and the card summary reading Exhibition · 60m games. Still locked once the event leaves Draft; switching still clears the schedule when games exist (recommended ruling D3).
  • The admin Schedule page — no Round Robin / Playoffs stage switch; View offers List and Timeline; Add Game stays the main button; the empty state says "Add your games by hand" and mentions the Round-Robin Generator only as the Plus upgrade; no Build Bracket button, no Bracket PDF.
  • The dashboard — before the event the shortcut "Set up a playoff bracket" reads "Add your games"; on game day "View the playoff bracket" reads "Print today's schedule"; when the last score lands the status pill flips to Ready to finalize and the card says Every score is final. Mark the tournament complete to lock in your results and standings. — no mention of champions, because there are none.
  • The public schedule — one list of games, no Pool Play / Playoffs toggle. Standings stay on the public page as today, and the organizer hides them with the existing Hide Standings switch if a scrimmage day should have no table (ruling D2). The public overview already knows how to finish a tournament with no bracket, so nothing changes there.
  • Help gains a sentence per touch-point for the third style. The demos do not change (recommended ruling D4).

Expected impact

A coach can set up a one-day scrimmage in the same number of taps as today and never see the word "bracket"; families see a schedule that promises exactly what will happen; the organizer gets the close-out prompt the same afternoon rather than the next morning; one fewer "do I have to build a bracket?" support question.

Trade-offs made

  • Switching a Draft's format with games already typed still deletes them all, even though Exhibition and Round robin + playoffs share identical round-robin games. Kept for this pass because the format is only changeable in Draft and a draft rarely has games; a smarter rule is a small follow-up if anyone asks (D3).
  • Exhibition still runs standings. A pure scrimmage day with no table is the existing Hide Standings switch, not a fourth format (D2).
  • The Round-Robin Generator stays a Tournament Plus feature; Exhibition does not unlock it for the standalone coach.

Priority

Medium — small build (about a day and a half including tests, help and review), no migration, no plan or gate change; it closes a gap between the marketing copy and the picker on the surface a new standalone coach reaches first. Sequence after the roster/player-page and development-lifecycle commits in flight so the review runs on a clean diff.

Success criteria

An organizer who picks Exhibition sees no Stage switch, no Build Bracket button and no bracket wording anywhere on the admin schedule; the public schedule for that event has no Pool Play / Playoffs toggle; the dashboard reads Ready to finalize the moment the last game is scored, and a round robin + playoffs event whose bracket is not built yet still does NOT (the original safeguard survives, pinned by a unit test); the word "Exhibition" is the only name the third style has anywhere a customer reads it.

Full assessment · 2026-09-13 · argued from what the code does

Exhibition — implementation plan

Status: proposed. D1 (name) and D2 (no fourth format) ruled 2026-09-13; D3 and D4 recommended on the Decisions tab. No code before Phase 0 (this mockup) is ratified. The repo copy of this plan, with file and line references, is docs/projects/active/TOURNAMENT_EXHIBITION_FORMAT_PLAN.md.

Goal

A coach (or any organizer) can pick Exhibition as the tournament's style and never be shown a bracket they are not going to build — not on the schedule, not on the dashboard, not on the public page — and the dashboard tells them they are done the moment the last score is in.

What the code does today

  • Where the format lives. A key inside the tournament's settings JSON — not a column of its own. Two values today; absent means round robin + playoffs. No database constraint, so a third value needs no migration. The admin API keeps an allow-list of accepted values; anything else is silently dropped from a settings write.
  • One helper answers one question — "is this bracket-only?" — and eleven places ask it: the admin preview layout, the bracket editor, the admin schedule page, the playoff wizard, the public tournament layout, the public schedule, the public-page visibility rules (three places) and one unit test.
  • Three pickers. The setup wizard and the org sign-up wizard each draw two cards and write the setting only when the choice is Bracket only ("the default needs no write"). Event settings → Schedule Rules has a two-segment control, locked outside Draft, with a confirm-and-clear-the-schedule flow when games exist — and it parses the stored value as "bracket-only, otherwise round robin", so any third value would silently read back as round robin + playoffs on that page. That parse is the trap the two-predicate refactor exists to remove.
  • Plan reality. The Premium Coaches Portal ranks with the free Tournament floor: the Round-Robin Generator and the bracket generator are Tournament Plus; hand-building games and a bracket is free. The standalone coach adds every game by hand.
  • Already tolerant of no bracket: the public overview (its third "finished" path is explicitly a no-bracket event that has played out), the Playoffs tab (needs a playoff config), the Playoff Picture and its countdown, champions (a decided final only), the summary's champions band, the standings' "Top N advance" caption, the "Playoffs are set" fan push, the coach-side phase model, and activation / completion (no bracket check).
  • Copy already promising it: the coaches marketing page ("your round-robin, exhibition weekend, or local event"), the coach portal's set-up card ("A quick round robin or exhibition weekend, set up from here") and the 2026-09-13 delegation ruling ("run the exhibition weekend").

Findings

F01 — The style picker offers two shapes and both end in a bracket

Wizard, onboarding and Event settings all offer Round robin + playoffs or Bracket only. The marketing page, the coach set-up card and the owner's ruling all describe an exhibition weekend. The picker is the only surface that contradicts them.

F02 — The admin schedule shows a Playoffs stage and a bracket callout on a tournament that has no bracket

The Stage toggle (phone row and desktop control) renders for every non-bracket-only event; the Playoffs side offers a Build Bracket primary; the empty-state callout ends "For playoffs, use the Playoff Bracket Builder."

F03 — "Ready to finalize" requires a bracket, so an exhibition never gets the finalize prompt on the day

The guard is deliberate (so a round robin whose bracket is not built yet never trips it early) and right for the two bracket formats. For an exhibition the rail stays on the live card after the last score and the close-out prompt waits for the calendar — the next day, on a one-day event.

F04 — The dashboard's shortcuts name a bracket before and during the event

"Set up a playoff bracket" pre-event; "View the playoff bracket" on game day. No format-aware alternative.

F05 — The public schedule shows a Pool Play | Playoffs toggle whose Playoffs side reads "No playoff games yet"

Both renderings of the stage control appear for every non-bracket-only event. A parent reads "Playoffs" as a stage that is coming.

F06 — The ready-stage copy says "Your champions are decided"

True for both bracket formats; false for an exhibition, which crowns nobody by construction.

Proposal (recommended)

  • P1 — A third value, and two predicates instead of one. The format type gains exhibition. Two helpers — has a round robin? and has playoffs? — replace the single "is bracket-only?" question, and its eleven call sites are re-pointed to whichever question each was actually asking. A fourth format then never needs a sweep, and the settings page's "everything else is round robin" parse is replaced by a validated parse of all three. The API allow-list gains the value. No migration.
  • P2 — Three cards, one segmented control. Wizard and onboarding draw three cards (three across on desktop, stacked on a phone) and write the setting whenever it is not the default. Event settings gains a third segment, a third description ("No playoffs — every game is a stand-alone game. Standings still run; hide the Standings page under Public pages if you don't want a table."), the summary reads Exhibition · 60m games, the lock note is unchanged, and the confirm dialog names whichever format is being switched to.
  • P3 — The admin schedule under Exhibition. No Stage toggle; the page pinned to its one list (the mirror of today's bracket-only pin); View offers List | Timeline; Add Game stays the header primary; the Bracket Builder launcher and the Bracket PDF item never render; the empty state reads "Add your games by hand — a day of scrimmages is a handful of rows. The Round-Robin Generator can build them from your teams with Tournament Plus." (the Plus half only when the plan lacks the generator); Schedule Health's subtitle reads Saved games.
  • P4 — The dashboard knows the format. "Ready to finalize" no longer waits for a playoff game when the format has none — extracted into a pure helper beside the stage resolver so it gets a unit test. The guidance card learns whether the event has playoffs: the pre-event shortcut becomes Add your games, the game-day shortcut Print today's schedule, and the ready-stage sentence drops the champions clause for an exhibition. The status pill then reads Ready to finalize the moment the last game is scored.
  • P5 — The public schedule under Exhibition. The stage control (both renderings) and the Bracket view option are behind "has playoffs"; the playoff-day auto-switch is a no-op. Nothing else on the public site changes; Standings stays and honours Hide Standings (D2).
  • P6 — Words. One sentence per help touch-point (the public-pages paragraph, the setup and schedule articles) via /docs; a changelog entry; the spelling gate sees one word — Exhibition. Demos unchanged (D4).
The alternative (not recommended): no new format — detect "no playoff config on any division" at render time and hide the same things. Cheaper by a picker, but the promise disappears only after the organizer has not done something, so every surface flickers between the two shapes as the tournament is set up, and the dashboard could never safely fire Ready to finalize early (the whole reason F03's guard exists). A format is a decision the organizer makes once; the surfaces should follow the decision, not guess it.

Phases

Phase 0 — Mockup ratified (this hub)

Owner reads the five screens on desktop and phone width and rules D3/D4. No code before this.

Phase 1 — The value and the pickers

The type, the two helpers, the retired one and its eleven call sites, the API allow-list, the three pickers including the settings page's parse, summary, description and confirm copy, and the write rule in both wizards.

Phase 2 — The surfaces

Admin schedule (P3), dashboard (P4, with the finalize predicate extracted and tested), public schedule (P5). The admin preview layout is unchanged — it hides Standings for bracket-only only.

Phase 3 — Words

/docs for the three help touch-points and their search keywords; a changelog entry; the spelling gate. Demos untouched per D4; check:demos must stay green.

Phase 4 — Verify and hand off

Typecheck (a shared type changes) and verify:changed. Tests: the public-bracket-visibility test gains an Exhibition fixture (Standings visible, no Playoffs tab, no bracket), and a new finalize test pins the predicate for all three formats — including the original case the guard exists for (round robin + playoffs, all pool games resolved, no bracket built → NOT ready). A rendered layout check of the three-card grid at phone / 641–768 / desktop. Then /simplify (the altitude pass confirms no call site still asks the old question), /review, /docs, a commit in a private index, and the owner QA walk added to this hub as its QA Walk tab (fixture: the uat-standalone coach org; steps pin identities, never figures the calendar moves).

Out of scope

  • A smarter format switch that keeps the round-robin games (D3 keeps the blanket rule).
  • A standings-less format (D2).
  • Any change to the plan gates — the Round-Robin Generator stays Tournament Plus.
  • Linking the coach schedule's Scrimmage event type to hosted exhibition games.
  • The history look-back layer — no route or page learns a year.

Verification and residual risk

  • The parse trap. After Phase 1 a search for the two old literal values outside the type, the helpers, the pickers, the allow-list and the tests should return nothing; any remaining literal is a place that will read an exhibition as one of the other two.
  • The finalize guard. The unit test must include the case that motivated the original guard.
  • Residual. A settings write of the new value against a not-yet-deployed API is dropped by the allow-list (the wizard already treats that write as non-fatal), so on stale code the picker degrades to round robin + playoffs — today's behaviour. Nothing to migrate: both old values stay valid.
