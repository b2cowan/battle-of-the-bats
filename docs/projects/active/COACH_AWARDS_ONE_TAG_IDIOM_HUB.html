Product-manager brief

Awards join the One Tag Idiom

Owner rulings 2026-09-11 · plan and brief in docs/projects/active/COACH_AWARDS_ONE_TAG_IDIOM_*.md

What it does

A coach can fix or take back an award right where they gave it, and the award chips themselves (MVP, Best Hitter, the ones the coach invents) get the same manage door, drawer and shelf every other tag in the portal already has — including merging duplicates.

Why it matters

Two dead ends today. An award given from a game can't be edited anywhere and can only be removed from a different page. And a mis-typed or duplicate award chip can be created inside the Give window but never fixed there — the only manager is a link buried on the season report, and it can only rename or hide, never delete or merge. When tags were settled on 2026-09-01 ("applies to every tag surface"), awards were the one vocabulary the review never inventoried. This closes that gap with the pattern coaches already know rather than a third way of managing words.

Who benefits

Every coach with the awards capability (head coaches, and any staff role granted awards). Club-shared award chips stay the club admin's to manage, listed read-only for the team — unchanged. No plan gating changes.

What changes for the coach

  • On a scored game — each award in "Awards given" gains Edit and Remove. Edit opens the same Give window, pre-filled, titled Edit award: change the player, the award, the note; Save. Remove asks once. Which game the award is for doesn't change (remove and re-give for that, same as a tag on the wrong event).
  • In the Give window — beside "+ New" the Award field gains Manage awards…. It opens the side drawer over the form: every award with how many times it's been given, rename (name and icon together), merge one into another, remove. Shared club awards list below, read-only.
  • Removing a used award is honest — the dialog says how many times it's been given and offers Merge instead (those players keep an award under the other name) or Retire (leaves the picker, stays on their record). An award never given just deletes. Nothing a player received is silently erased; nothing is stuck forever either.
  • A player holds an award once per occasion. Giving Blake MVP for a game he already has MVP for is refused with a plain sentence — same on Edit. Today nothing stops that double; it was possible all along, and merging would only have made it visible. When a merge would leave someone with the same award twice for one game, it keeps the one given first and says so before you confirm: "4 awards become MVP. 1 is dropped — Blake would hold MVP twice for the Apr 16 game." The same award on a different game is still fine — "2× MVP this season" stays real.
  • Team settings → Tags gains an Awards row. The report page's old "Manage award types" link goes — one way in.
  • The season report gains Edit beside its existing Print and Remove on every history row.
  • Everything that reads awards — a player's profile, Season Wrapped, certificates, the family recap — picks up a rename or merge automatically. A closed season stays a record; none of these tools reach it.

Expected impact

Duplicates ("MVP" and "MVP (2)") become a ten-second merge instead of a permanent picker; a mis-given award is a two-tap fix at the game instead of a trip to the report to delete and re-give; a new coach learns nothing new — it's the tag drawer, holding awards.

Trade-offs made

  • The award picker stays a chip row (tap one of five), not the searchable dropdown tags use — the list is short and carries icons; budget items and test types kept their own shape under the same ruling.
  • An award can't be moved between games in place.
  • The three starter awards a new team gets will stop re-appearing after a coach deletes them (today's seed re-runs whenever a team has none); whether a new team still gets a starter set at all is the one open call.

Priority

Medium-high. Small in scope — two contained phases on a pattern that already exists — and it removes a genuine "the product won't let me fix my mistake" moment on a feature that sits in the demo's shop window and the marketing shots. Part A is a half-day contained fix; Part B needs one migration (a merge function) and rides the next release's migration order.

Success criteria

  • A coach can edit and remove an award from the game drawer and the report page; the schedule's trophy count updates the moment they do.
  • Two same-meaning award chips can be merged from the Give window, and every award already given under the loser reads under the winner on the game, the report, the player profile and Season Wrapped — nothing lost.
  • Removing a used award never orphans or cascades; the dialog states the count and offers merge or retire; an unused one deletes.
  • The Tags shelf lists Awards; the report page has no "Manage award types" link; help and the marketing shot say what the screen does.
  • Owner QA walk passes on this hub's QA tab; the demo check stays green on both worlds.
Full plan — readable version

Awards join the One Tag Idiom — implementation plan

File-level detail (paths, route shapes, test names) lives in docs/projects/active/COACH_AWARDS_ONE_TAG_IDIOM_PLAN.md. This tab is the same plan in plain words.

Problem / context

Two things are called "awards." A given award is the record — Blake got MVP for Apr 16. An award chip is the type — MVP itself, with its icon. Today a given award can be created from the game drawer and removed only from the season report page, and edited nowhere. An award chip can be minted inline with "+ New" but managed only from a separate modal reached by a text link on the report page, and that modal can rename or retire — never delete, never merge, and it shows no usage counts. The 2026-09-01 tagging ruling settled how every tag vocabulary works (one door where minting lives, one drawer manager with counts and rename / merge / delete, a Tags shelf under Team settings) and says it applies to every tag surface — but award chips were never in that review's inventory.

Scope

Part A — Edit and Remove on a given award, on the game drawer's award rows and the report's history rows; the Give window reused in an edit mode; the schedule's trophy badge kept true after a write. Part B — the award-chip library joins the idiom: usage counts, delete (unused) and merge on the server; the "Manage awards…" door beside "+ New"; the ratified drawer holding awards (name + icon rename, merge, remove with the merge-or-retire dialog, a Retired group with Restore); an Awards row on the Tags shelf; the report page's "Manage award types" link and its modal retired; the read-time starter seed replaced or removed. Then help, the marketing shot, the demo check, and the owner walk.

Out of scope

The club admin's Shared Library (its own manager for shared awards); the closed-season page and every read surface (profile, Season Wrapped, recaps, certificates) — records, untouched, and they resolve names through the chip so rename/merge propagate for free; moving a given award to a different game; adopting the search dropdown as the award picker; an edit history on a given award.

Approach

  • One list, a declared policy — not a sibling manager. The tag manager is one component rendered in two frames (drawer and shelf), and the parent ruling's load-bearing sentence is that its behaviour must never fork. Awards differ in exactly three declarable ways — an icon, "given N times" as the count noun, and merge-or-retire instead of orphan on remove — so those become a per-library policy rather than a fourth hand-copied manager.
  • Remove on a used award = merge or retire; never orphan, never cascade. A tag is a label; a game with one label fewer is still a game. An award is a record key — the database itself refuses to leave an award without a type — and "Blake got ___" is not an award. Cascade would erase recognition players received. Retire already exists and is the honest "stop using it."
  • Counts are all-time, not this-season. The dialog's claim is "does anything depend on this chip" — a chip retired last year with ten records must still refuse delete.
  • Once per occasion is a database rule, not only a form rule (R5). The refusal on Give/Edit could live in the form alone, but the merge's collapse has to be able to rely on the data actually being that way, and a form check can't promise it (two tabs, a retry, an import). "Occasion" for a general award is its date plus its label — the only identity a general award carries. A collapse keeps the award given first; a dropped note is carried only into an empty slot, so nothing a coach wrote is lost or overwritten silently.
  • The chip row stays as the picker. The search dropdown exists because a 50-item vocabulary is searched; a ≤30-item curated list with icons is tapped. The door adopts the idiom's grammar in chip form.
  • The game an award is for is not editable. Player, award, note and (for a general award) the occasion are what a mis-tap gets wrong; a wrong game is remove-and-re-give, like a tag on the wrong event.
  • The read-time starter seed goes. It re-runs whenever a team has zero chips — harmless today, a trap once delete exists (remove all three, they come back). Either a one-time seed at team creation replaces it or the seed goes entirely (open question).

Phases

Phase 1 — Part A: fix or take back a given award where it was given (no migration · ships alone · builds first)

  • An update path for a given award: player, award, note, and the occasion label for a general award; the game stays fixed; the record's "last changed" stamp is written.
  • Give and Edit refuse a second copy of the same award for the same player on the same occasion, with one sentence (the database rule that makes it airtight arrives in Phase 2 — the hole exists today, so the form refusal doesn't wait).
  • The three hand-copied auth guards on the award routes collapse onto the shared live-season guard.
  • The Give window gains an edit mode — pre-filled, titled Edit award, primary reads Save changes, no remove link inside the form.
  • The game drawer's award rows gain Edit and Remove; the report's history rows gain Edit beside Print and Remove; the schedule's trophy badge is derived from the awards so it's true the moment one is given, edited or removed.
  • Unit tests on the update rules; help gains one sentence per article; rendered check on the drawer at phone widths; simplify, review, owner walk.

Phase 2 — Part B, step 1: counts, delete and merge on the server (migration 289 first)

  • Before anything is written: ask both databases whether any award is already doubled; the migration collapses each double to the earlier award, and the count it touched is recorded — a data step no schema gate can see.
  • The once-per-occasion rule itself (a player, an award, a game — or a date and label for a general award), so the form's refusal is a fact about the data and the merge can rely on it.
  • A merge function that first collapses collisions (keeping the first-given, carrying a note only into an empty slot), then re-points every remaining award from the losing chip to the winner and removes the loser, in one transaction, scoped to the team — and reports how many moved and how many dropped. A preview of the same numbers feeds the confirm dialog before the tap. A delete policy for parity with tags. The database's existing refusal to leave an award without a type stays as the backstop.
  • Data dictionary updated and snapshots refreshed in the same unit of work.
  • Usage counts per chip (all-time, team-scoped) returned with the library; delete for an unused chip; a used chip's delete answers with the count and the two exits so the client never guesses; merge.
  • The read-time starter seed is removed (or moved to team creation, per the open question), pinned by a test that a team with a deleted starter reads an empty library.

Phase 3 — Part B, step 2: the door, the drawer, the dialog, the shelf (no migration)

  • The shared manager list takes a per-library policy: icon on the row and in rename; "given N times"; the merge-or-retire remove dialog; a Retired group with Restore.
  • "Manage awards…" beside "+ New" opens the drawer over the Give window (form dims and waits, selections kept; full-screen sheet on a phone).
  • An Awards row on the Team settings Tags shelf, shown only when the coach can read the library.
  • The report page's "Manage award types" link and its modal are deleted; the stylesheet's shared classes are checked for other consumers before anything is removed.
  • Tests on the policy switch and the door; spelling gate; rendered sweep at four widths including the shelf opened; simplify, review.

Phase 4 — Words, help, demo, marketing, walk

  • Help: the "rename or retire an award" FAQ becomes the drawer story (rename, merge duplicates, remove or retire with the rule stated plainly, the Tags shelf as the second home); the give-award and Who's-earning-it answers stop naming "Manage award types"; keywords keep the old phrase for search.
  • Demo: no narration names an award door (verified) — the demo check proves both worlds still present. A merge leaves no trace, so no new demo moment.
  • The marketing shot of the awards report is re-photographed (Edit now sits in its last column).
  • Owner QA walk on this hub's QA tab, pinned to identities (the fixture's duplicate chip; Blake's award on the Northgate game), never figures; ledger section; TODO trued to anchored facts; stage strip advanced.

Open questions

  • Keep a starter set of three awards for a new team? Recommendation: keep it, seeded once at team creation — a new coach opening Give an award to an empty chip row is a colder first moment than tags' "type a word." If every award should be one the coach made, the seed goes entirely and the help line naming the three is swept.
  • Count noun in the drawer: "given 4 times" vs "on 4 awards" — decide on the built screen.
  • Should the club admin's Shared Library get merge/remove for shared chips? Not here — a different screen and actor; noted for that stream.

Rollout

Phase 1 ships alone (no migration). Phase 2's migration is rule-adding, so it must be applied to production before the master build that carries Phase 3 can go green — the standing order from the 2026-09-10 release. It also carries a data step (collapsing any already-doubled award) that no gate can see: production is queried for doubles first and the count recorded, never assumed zero because dev had none. No seeded demo change; the demo check runs after each phase. Help and the marketing shot land with the door, in the same unit of work.
