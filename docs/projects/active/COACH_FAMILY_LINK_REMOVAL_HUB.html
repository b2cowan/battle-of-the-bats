Family link removal

What changes for the coach

The Team family access section disappears from the bottom of the Roster page. A coach can no longer create a family link, nobody can use one to ask to follow the team, and there is no follower list or approval queue to tend. The Roster page ends where the roster ends.

The one control on that card that still does something — Schedule visibility (Staff only / Families / Public link) — moves to Team settings → Sharing. Same three settings, same meanings: Staff only keeps games and practices inside the coaching staff and stops a shared game page opening; Families lets connected people see the full schedule; Public link also puts it on the team’s public page.

Nothing else in the family layer changes: a player’s parent or guardian still has their family portal (behind the platform-wide guardian switch, which stays off pending the privacy review), the coach still previews the family season recap on a player’s page, sharing a single game link still works, and the club admin still sees how many families are connected per team.

Why it matters

Grandparent-and-relative following was a door the owner has decided the product does not need. Leaving the card in place would keep showing every premium coach a “Create link” control for a path that is being retired, and would keep an unused approval queue on a page coaches visit every week.

Customer impact

No customer loses anything they were using: on production, no team has ever created a family link and no follower exists. Every premium coach sees a shorter Roster page and finds Schedule visibility in Team settings the next time they look for it. The in-app help guide is rewritten to match, and the help drawer on Roster no longer points at the family-access guide.

Priority

Owner-directed, 2026-09-12. Small in customer impact; medium in code (a database step is part of it, see the plan) — worth doing in one sitting so the roster page and the help guide never disagree.

Success criteria

  • No coach screen, help article or API offers a way to create, share, request through, approve or reset a family link.
  • Schedule visibility is set from Team settings and still governs the public team page and sharing a game.
  • Guardian portal, family recap preview and game-link sharing behave exactly as before.
  • The build gates stay green: type check, unit tests, help-search spelling, dictionary coverage, schema parity once the migration is on both databases.
Full assessment

Family link removal — implementation plan

Plan of record: docs/projects/active/COACH_FAMILY_LINK_REMOVAL_PLAN.md (carries the build ledger and the rollout detail). This tab is the plan as approved, rendered for reading.

Problem / context

The Team family access card shipped with Chunk D, Slice 1 (2026-08): a team-level link a coach shares, families ask to follow through it, the coach approves, and followers see the schedule and results. The owner asked on 2026-09-12 for the family link functionality to be removed, and ruled the scope as the link and followers: Schedule visibility survives (relocated), and the guardian portal survives untouched.

Dev and prod run identical code here. The panel hides itself only when a team is not entitled to the premium portal; the one real team on production is entitled and sees this card too. “Make dev like prod” therefore has no code meaning — the removal is the whole job.

F01 — The family link and everything that exists because of it

Today: a coach mints a link (Roster → Team family access → Create link), families open /family/join/…, sign in, choose follow (or guardian, which the switched-off guardian tier refuses), and the request waits on the same card for Approve / Decline; Manage lists followers with Remove; Reset link kills every shared copy. Proposal: all of it goes — the card, the link mint/reset, the join page and its API, follower request/approve/decline/revoke, the follower safety ceiling, the follower split in the club admin’s counts, and the three link columns on the team record.

F02 — Schedule visibility loses its home

Today: the setting lives on the card being removed. Proposal: it moves to Team settings → Sharing, served and saved by the team settings API, gated on the same permission as sharing a game (head coach, or an assistant who manages the schedule). Absent — never locked — for a team that is not on the premium portal, matching how the Club Shared Book switch already behaves.

Scope

Release notesOne entry: the card is gone, the setting moved.
Out of scope

The guardian tier and its portal, the family season recap, the keepsake card, calendar feeds, sharing a single game, the club admin’s connected-families counts, and the demo sandbox (which seeds guardians, never followers, and narrates neither). Undoing the August premium-packaging decision is not implied — the family layer stays premium.

Approach

Delete rather than hide. A hidden panel with live endpoints behind it is the “write controls the server refuses” shape the coaches portal rules forbid. The migration goes in the same unit of work as the code, because a column nothing reads is schema drift the gates cannot see. The alternative — leaving the columns and the follower role in the database “in case” — was rejected: it keeps a retired concept alive in the dictionary and every future reader has to be told it is dead.

Open questions

None blocking. One consequence worth knowing: with the link gone, a parent can only enter the guardian tier (when it opens) through a coach-sent invite, not by asking through a team link. The help guide says so.

Rollout

  • Migration 290 applies to dev with the build; it is prod-owed and order-critical — the master build’s schema-parity gate fails until it is on production, so it is applied before or with the release, never after.
  • No demo re-seed needed: neither sandbox seeds a follower or mentions the link.
  • Dev server restart at hand-off (files deleted, shared modules changed).
