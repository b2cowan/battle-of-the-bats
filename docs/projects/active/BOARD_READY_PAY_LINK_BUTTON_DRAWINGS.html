Who sees the line, and when

  • Who: the club owner, admins and anyone given “Run tournaments”, the same people the server already lets email a pay link. The treasurer’s Accounting seat, scorekeepers, check-in volunteers and coaches don’t see it (ask 2).
  • When: on every accepted team while the tournament takes card payments, and on any team that ever paid by card, even one later declined, because its link still shows receipts.
  • The menu holds: “Email the pay link” only while the team can pay now, which is today’s rule. “Send a new link” when it can pay now and has an email. Otherwise “Stop the pay link” (ask 3).
  • Pressing it twice: the item stays in the menu after a stop. Pressing again stops whatever link is current, including the one behind the coach’s own Pay button.
  • Not here: the coach portal. A coach’s own Pay button always opens the current link, so it keeps working after a replacement with nothing to do.

Why “Only stop the link” is on the dispute window

The amber note is the shipped dispute words, in the window’s own note above the buttons. The three buttons wrap to a second row at this width, as drawn. An organizer who opens this for a team that lost a dispute probably wants the old link dead and no new card payment invited. Today the server stops the link first and asks about the dispute afterwards, in a second window. The proposal asks first, in this one window, and offers both answers (ask 6).

Build size if ruled: the record already reads each payment’s dispute, so it knows before the window opens. The server needs a “stop only” answer and has to check the dispute before it stops, about a day’s work with its tests.

Pressing “Send a new link” here stops the old link and sends the new one in one step. It never opens a second window.

The answer shows in the record, on the pay-link line

Today’s “Email the pay link” answers with a quiet status line in the record, not a toast. Send a new link does the same, so the organizer’s eye stays where they clicked. The line itself then says the link was replaced (ask 7).

No copy button (ask 4)

The new link goes by email only, as it does on the house-league side. A copy button would invite the organizer to paste it into a group chat, which is how a link ends up in the wrong hands in the first place. Neither side has a copy control today.

What keeps working

  • A payment already on the card page. It goes through and the team lands on the new link’s receipt. The server does this already.
  • Not covered: someone who had the old pay page open but hadn’t pressed Pay. Their press is refused with the line on the left, and they need the new email. The build can leave this gap. Closing it would mean letting an old link pay for a moment longer, which works against the point of the button.
  • The coach portal. A coach’s own Pay button builds the current link every time.
  • Every pay-link email from now on, while the team can pay: acceptance, reminders, receipts and bank-debit emails all carry the current link.
  • What stops: every copy of the old link, in any inbox, forwarded or not.
