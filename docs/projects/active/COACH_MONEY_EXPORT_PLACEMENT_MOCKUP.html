Where Export lives

Budget vs. Actual grew a second Export button, and it was not a slip — it was the first sign that Import and Export are not the same kind of door. One is hub-wide by nature. The other can only ever be honest about the screen you are standing on.

The fault

Two buttons, both saying Export, forty millimetres apart — producing entirely different files.

The month grid — one column per month, at the chosen reading.

The one at the top exports the category table. The one in the view bar exports the month grid, at whichever of the four readings is selected. Nothing on screen says so. A coach who has just set the grid to Difference and reaches for the obvious button at the top gets a file with no months in it at all.

This is not a Budget vs. Actual problem. Budget Plan has List and By period. Expenses & Payables has three sub-tabs and a tag filter. Every tab carries arrangement the header cannot see — Budget vs. Actual is simply the first one where the mismatch grew a second button and became visible.

Two jobs, one word

The hub menu was built for the first of these. Every tab keeps quietly needing the second.

“Bring this into Money”

Budget lines, or a payables schedule. It does not matter which tab you are standing on, and nothing you have arranged on screen changes what happens. There is one right answer per dataset, always.

Belongs in the header

“Take out what I am looking at”

The month grid at the reading you chose. The payables sub-tab, not the expenses one. The plan by period rather than as a list. Filtered to a tag. A hub-wide menu cannot see any of it, so it can only ever offer a generic version and hope that was what you meant.

Belongs on the page
This is the rule already agreed, applied one step further. A button belongs to the nearest chrome that names what it acts on — which is why the creates came down out of a header that said “Money”. An export that depends on a picker two hundred pixels below it is orphaned in exactly the same way. Import survives the test; Export does not.

The decided shape

Import stays at the top. Export moves down into the control row each tab already has — beside the switches that decide what it will contain.

The month grid — and the file you get is this grid.

One Export, and it can only mean one thing: what is on screen, arranged the way you arranged it. The “which shape did you mean?” question stops existing rather than being answered. Picking it still opens the Choose a file type dialog — that part is unchanged, and it is now the one place the question gets asked anywhere in the hub.

Every tab already has this row. It was built as one shape during the action pass, and it is where Add Line, Add Expense and New Fundraiser now live. Export joins it as the right-most item on every tab that has data to give — so it is not five different placements, it is the same placement five times.

On a phone

The phone rule was written about the header. Moving the button does not move the reasoning — it was never about where the button sat, but about what the file is good for.

Export survives — as PDF alone. A dues statement is something a coach shows a parent standing in front of them. That is phone work; a spreadsheet is not.

The rule gets simpler, not more complicated. Before, it was “the phone header drops imports and spreadsheet exports”. Now it is “a phone is offered an export only where the file is something a coach can read, show or send” — which is what it always meant. Two tabs keep one (Player Dues, Budget vs. Actual, both PDF); the rest do not, and Import keeps its survival route through the empty states exactly as before.

What we give up

CostHonest assessment
One place to see everything exportable Real, and it was the original complaint. But the complaint was “only two of seven tabs have an export” — and the fix for that is every tab having one in a predictable spot, not one menu listing them all. A coach goes to the tab whose numbers they want, which is where they were looking anyway.
“Which datasets make a PDF?” No longer answerable from one screen. It was not answerable from the menu either after the file type moved into a dialog — the in-app Money guide names them, and that stays true.
Work already built today The dataset menu and its dialog are done. The dialog survives unchanged. Roughly half a day of the menu goes; better spent than shipping a door that lies about what is behind it.
A third decision on one surface in one day Worth naming. Each was made from a render rather than a description, and each was cheaper than the one before.
Separately, and not in this change: these screens do not agree with each other about what a table looks like — a bordered grid here, white stacked cards there, a third treatment on Player Dues. Each is defensible alone; together they make one hub look like three products. That is its own pass, with its own inventory and its own renders.
