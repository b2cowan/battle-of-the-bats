What “checkout” is on dev (read from the code and the settings, nothing was run)

  • Coaches Portal checkout is open on dev (plan_gating row for team reads live). Dev holds Stripe test prices for Team, monthly and annual, and a sk_test_ key.
  • The “apply it directly, no Stripe” mock is off by default: ENABLE_BILLING_MOCK_PORTAL is not set. So out of the box, Continue to checkout opens a Stripe test page. Pay with test card 4242 4242 4242 4242, any future expiry, any three digits, any name and postal code.
  • On the Stripe route the portal is changed by Stripe’s webhook, so a listener must be running: stripe listen --forward-to localhost:3000/api/billing/webhook (the Stripe command line tool is installed on this PC; none was running when this was written). Without it the page after payment stays on “setting up” and nothing converts.
  • The other route is the mock: console › Dev tools › Mock billing › Enable mock. Then Continue to checkout applies at once with no card page, and you land straight in the portal. It lasts until the dev server restarts. ⚠ Under the mock the subscription id is fake, so path 3’s cancel shows an error (Stripe does not know it) although the portal does cancel. Prefer the Stripe route for the whole walk; use the mock only if the listener will not run.
  • Premium has no trial (Team trial is 0 days on dev too). On a real checkout the coach is charged at once, and any free days left are given up. That is call 1, yours to rule.
