Two things to know before you start (found while building this walk)

  • Stripe’s test messages reach the deployed dev site, not this computer. That site runs the code from the last push, which does not have step 6.4 yet. So today the purchase email is sent by the daily job’s catch-up, not the moment you pay. Two small commands do it: $FIX settle (fills a field the older code leaves empty) then $FIX run-daily. This walk proves the email’s words, figures and once-only rule; it cannot prove the “within a minute” part. That needs the dev branch pushed so the deployed site runs 6.4: your call, listed at the foot. The same older code may also send its own old “Welcome back” email in Part H; that one does not count against 6.4.
  • One defect is already known in the reminder. A yearly plan whose cancel was set only inside Stripe gets no email (correct), but the daily job counts it as a failure every day instead of skipping it quietly. It is a step in Part F where you choose what to do about it.
