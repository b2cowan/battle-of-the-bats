Sign-in & security, and “type your code again”

Every Account page now has a Sign-in & security section: two-step sign-in in its states, Set up a new phone, New backup codes, Turn off (only where nothing requires it), Sign out everywhere else, and Change password. Six actions ask for your code if the last one was over 15 minutes ago, in one small window that then finishes what you pressed. The code step gains Lost your phone?. Four walks, one purpose each. About 45 minutes (walk 4 starts at least 15 minutes after walk 1), and you need an authenticator app on your phone.

Not in this walk: the club’s two switches and the 14 days (Part 3, which also brings the club’s version of “Lost your phone?” and the reset that uses this window), and the Members column, Overview notice and emails (Part 4). The “required, set it up by …” state needs Part 3’s switch, so it is walked there.

Before you start

  • Walk 1 first. It turns two-step on for the club owner. Walk 4 must start at least 15 minutes after walk 1’s last code; walks 2 and 3 fill the time.
  • Walk 1 changes the club owner’s password and back: if you stop half-way, the password may be devpass456.
  • Walk 4 ends by turning two-step off for the club owner, so the account is as it was. support@dev.local keeps it on.
  • The drawings these screens were built to: tabs 4 and 5. The “type your code again” window was not drawn; it is built from tab 8’s “Stop requiring it” window.

Already proved by tests and my own pass (don’t re-do these)

  • Each of the actions asks before it writes or hands out a link (a build check per action), and a person with two-step off is never asked.
  • A session with only the password cannot reach Turn off, Change password, New backup codes or Set up a new phone, and a seat that requires two-step can never turn it off. Turn off’s order leaves two-step on if anything fails part-way, and a deliberate swap of that order is caught by the build.
  • Setting up a new phone while you still have the old one adds the new one first and removes the old one only once the new one works. With a backup code (a lost phone) the account stays protected the whole way; an authenticator someone sets up on the side with only the password counts for nothing, and is removed when you finish (a review fix).
  • Change password checks the current one without touching your own session (proved on dev: the check’s own session is ended at once), saves, and signs out your other devices.
  • The 30-day ask on a page already open uses the same window; staff’s “sign in again” is the same window and now takes a backup code.
  • New backup codes are stored with a keyed hash on dev. Codes made before keep working.

Your time goes on judgment: does each state say what is true for this person, does the window read as “one more step” rather than an error, and does the lost-phone screen help without telling a stranger anything?
