The form is ~250px shorter for a Game. On a phone that is the difference between Opponent above the fold and below it.

What changes, and why

1

The event type is asked twice changed

Every door into this form has already chosen the type: the Add Event menu lists Tournament / Game / Practice / Team Event, the practice hub opens it as a practice, and a tournament opens it as a tournament game. The title then says “Add Game” — and the pill row asks again. Neither pills nor a dropdown is the answer; the question is already answered.

Proposed: remove the row. The title carries the type, with the event's colour mark beside it (the same mark the schedule row and the menu wear). Picked the wrong type? Cancel and pick again — one tap, and the discard guard only asks if you've typed something.

2

“* Required” is the first thing a coach reads changed

The asterisk convention was ruled on 2026-08-25 as carrying the whole signal on its own — plain, in the label's ink. The forms built since (Record money, Add a goal, Record a result, Record an observation, Give an award) carry no legend. Here the legend explains a marker that sits on one field, Starts, which opens pre-filled — so it announces a requirement the coach never meets empty.

Proposed: drop it. Seven older forms still carry the same line (Add Player, Add Budget Line, dues credit, the head-coach editor, the free schedule editor, the interest form, the installment plan) — sweep them in the same pass so the portal keeps one rule.

3

The boxed, tinted sections — the “blue background” changed

When / Where / Who each sit in a filled, bordered card inside the modal. In the warm theme the fill is olive; in dark mode the same box tints blueprint-blue — that is the blue you remember. Either way it is a card inside a card, and the inputs then sit on a tinted ground (the same shape the Staff screen dropped this month). The rest of the portal's forms are flat: eyebrow labels, fields, space between groups. And the section words repeat the labels beneath them — “Where” over a field called Location, “Who” over Opponent — in a second grey-caps size so close to the field labels that they read as one level.

Proposed: flatten. Keep the grouping as a wider gap; drop the fill, the border and the headings. The one CSS rule behind these boxes also draws the open “More” disclosure, the Give Award sheet and the paste-a-roster sheet — change it once and all four agree.

4

Round buttons and a Title Case label changed

This is the only form in the portal whose footer buttons are pills — the stylesheet says so in as many words (“scoped to the event modal so the rest of the app's square buttons are untouched”). And “Save Event” is the portal's one Title Case save; everything else is sentence case (“Save changes”, “Add it”, “Save result”, “Record money”).

Proposed: the ordinary square buttons, and the verb from the title: Add game / Add practice / Add tournament; editing keeps “Save changes”. A repeating series already names its count (“Add 11 games”).

5

Home / Away as a segmented row your call

By the 2026-08-22 ruling a form field that picks one value is a dropdown, and every sibling pick on the money and roster forms (method, position, who raised it) is one. Drawn that way here, beside Opponent, it also lets the two game questions share a row. The honest counter-argument: three fixed words that will never grow, and “Away” is one tap today versus two.

Proposed: the dropdown, for one shape across every form — but this is the one item where the rule and the screen can reasonably disagree.

6

One field, two names changed

The same time is labelled “Arrival / call time” on a one-off event and “Arrival time” on a repeating one, on the same form. The one-spelling rule is about words, but the principle is the same: a thing has one name.

Proposed: “Arrival time” everywhere on the form. The hint under it stays — it is the one place a coach learns families see it.

7

“Add details (optional)” changed

The other disclosures name what is inside them — “More — success, tag”, “More — payee, tags, notes” — so a coach knows where Uniform went without opening it. And “(optional)” is the tag the 2026-08-26 ruling retired: the dashed line and the plus already say it.

Proposed: “More — field, uniform, tags, links, notes” on a game; “More — field, address, links, notes” otherwise.

8

Under the hood: it is not standing on the shared modal changed

Twenty forms stand in the portal's one modal shell; this one is hand-built. The visible cost is the drift above — a private width (600px, beside the shell's 520 and 640), the private pill radius. The invisible cost: Escape does not close it, focus is not trapped or returned, and a screen reader is never told it is a dialog — the floor every other form got, and the event slide-over on this very page got on 2026-09-20.

Proposed: stand it in the shared shell (the wide, scrolling variant). That is what keeps it from drifting again.

Optional — ask the date once your call

Separate from the consistency pass, so it can be ruled on its own. Today a one-off game asks for a date twice (Starts and Ends each carry one), while the repeat branch already asks the way people think: which day, what time, until when. The same shape for a one-off event would look like this. A multi-day tournament keeps its own Start date / End date.

PM Brief — the Add Event form looks like the rest of the portal

Ruled 2026-09-21 · built on dev the same day · plan on the Full Plan tab

What a coach sees differently

Open Add Event → Game on the Premium schedule.

  • The form opens on the fields, not on a legend. No "* Required" line; no row of event-type pills. The title says Add Game with the game's colour dot beside it — the same dot the schedule row and the Add Event menu use. Picked the wrong type? Cancel, pick again.
  • Date · Start time · End time on one row, then Arrival time. Before, the date was typed twice (once inside Starts, once inside Ends). The repeating form already asked it this way.
  • The When / Where / Who boxes are gone. The same fields sit flat on the sheet, in groups separated by space — the way Record money, Add a goal and every other form in the portal reads. (The "blue background" was this box in dark mode; olive in the warm theme. Same box.)
  • Opponent and Home / Away share a row; Home / Away is a dropdown like every other pick in the portal. The "@ vs vs" hint sits under the row. "This is a scrimmage" is unchanged.
  • The optional group is named for what it holds — More — field, uniform, tags, links, notes — instead of "Add details (optional)".
  • The footer is the ordinary square buttons: Cancel · Add game (Add practice, Add tournament, Add team event; a repeating series still says "Add 11 games"; editing still says Save changes).
  • Escape closes the form, focus returns to where you were, and a screen reader is told it is a dialog — the floor every other form already had.

Net: the Game form is roughly 250px shorter; on a phone, Opponent is above the fold.

What else it touches

  • The same rule that drew the tinted boxes draws the open "More" group on every form, the Give Award sheet and the paste-a-roster sheet — all four flatten together, so nothing is left as the odd one out.
  • The "* Required" line comes off the six other forms that still carried it (Add Player, Add Budget Line, dues credit, the head-coach editor, the free schedule editor, the interest form).
  • "(optional)" tags come off the premium forms that still had them (Give an award, Add a goal, Record a result, Review a goal, the skill/test definition sheet, the game console's "About a player?", the scouting note, the budget period grid). The free-tier editors keep their older "+ Add … (optional)" panels — a separate call.
  • The help articles say Arrival time where they said "Arrival / call time" (searching "call time" still finds them).

Why it matters

A coach meets this form more than any other on the portal — every game, every practice. It was the one form still speaking an older visual language, and every difference cost either space (the pills, the legend, the boxes) or a small doubt (is this the same product?). The pass spends no new design; it applies rulings already in force.

Trade-offs

  • Changing the type mid-form now means Cancel + re-pick (one tap; the discard guard only asks if something was typed). Chosen over keeping a whole row on every open.
  • An event that crosses midnight (23:00–01:00) is recomposed same-day if edited. Youth-team events do not cross midnight; the repeating branch already assumed this.
  • Home / Away as a dropdown is one more tap for an away game than the segmented row was. Ruled for one shape across every form.

Full plan — the Add / Edit Event form, held to the portal's own form rules

Ruled 2026-09-21 (all nine items) · built on dev 2026-09-21 · source: docs/projects/active/COACH_EVENT_FORM_CONSISTENCY_PLAN.md

1. Why

The event form was built before several standing rulings and drifted against each of them: "a one-value form field is a dropdown" (08-22), "one plain asterisk — mark the few required, never the many optional" (08-25/26), "never a filled CTA on a panel tinted with its own hue" (07-30, and the Staff screen's 09 drop of the tinted panel), the List · Room · Question shell (twenty forms stand in it; this one was hand-built), and the portal's sentence-case, square-button footer. A screenshot read ("blue background", "* Required first", "pills or a dropdown?") was the trigger; the review widened it to eight items and one optional idea.

3. How "date once" is built

The two datetime values stay canonical — the save, the guards, the tournament prefill and the mirrored facts read them unchanged. The three visible pieces are the form's existing date / start-time / end-time fields (the repeat branch's own): seeded from the datetimes wherever the form is built, and recomposed on every edit. The "end follows the start by two hours unless the coach set a custom end" rule survives. Clearing a piece leaves the others on screen and greys Save. Toggling Repeat weekly now opens with First date pre-filled. Known limit, accepted: an event ending the next day (23:00–01:00) is recomposed same-day when edited.

4. The sweep

  • Legend removals: Add Player (keeps the "Adding several? Paste a list →" line), Add Budget Line, dues credit, head-coach editor, free schedule editor, interest form.
  • Flattened by the one rule: open disclosures everywhere, Give an award, Paste a roster.
  • "(optional)" labels, premium forms: Give an award (2), Add a goal (3), Record a result, Review a goal (2), the skill/test definition sheet, the game console's "About a player?", the scouting note, the budget period grid (2 + one accessible name). Out of scope: the free portal's older "+ Add … (optional)" panels.
  • Help: the game-day-details term and FAQ say Arrival time; the schedule article's Premium line says "arrival time".
  • Retired: the event modal's private width and pill-radius rule, the in-form type-picker styles and their warm overrides, the pill list constant. The dot survives as the title mark. The sticky scope chooser now lands flush the way the footer does (it used to rely on the retired class).
  • New: a three-column grid for Date · Start · End (≤640 the date spans the row, the two times share the next); a title-with-mark style.

5. Verification

  • Typecheck clean; the changed-files gate clean (spelling, dictionary, CSS selectors, contrast, the unit suite).
  • The schedule smoke UAT drives recurrence through the API, not the form's controls — no locator changes.
  • Browser: the QA Walk tab (§212).

8. Open for the owner

The bill's payment-schedule editor is now the portal's one remaining tinted form section (its own approved drawing from 2026-08-29). Flatten it under the same ruling, or keep it as the one place where rows-on-a-surface was the design? Not decided here.

6. Not built, on purpose

  • No "change the type inside the form" affordance — the door is one tap away.
  • No custom calendar glyph on this form — it lives in the budget module; adopting it here is a shared-primitive move for its own session.
  • The free-tier editors' "(optional)" idiom.
