Product-manager brief

Save over a practice template, a drill or a circuit

What changes for the coach

Practice plans have three saves: a whole practice as a template, one activity as a drill, and a block of stations as a circuit. Today all three only create. If you already have one with that name, the save is refused after you press the button. With this change, all three can save over the one you have, the same way the lineup builder’s Save as template does now:

  • Each save window has a name field, already filled in. A new name saves a new one. A name you already have turns the button into Replace (templates) or Update (drills, circuits).
  • The button leads to an are-you-sure inside the window. It shows what the saved one holds now and what it will hold, then gives a red confirm button and Keep it.
  • Tags are replaced by the ones being saved. A template takes the practice’s tags. A drill or circuit takes the tags picked in the window, which start as its current tags so nothing is wiped by accident.
  • An updated drill reaches upcoming practices. Every practice that hasn’t happened yet and still has the drill linked gets the new words. Practices that already happened keep the version they ran. The question names the upcoming practices before you confirm.
  • A block placed from a circuit gets a Save to my circuits… door, so tonight’s better version can go back to the circuit.

Two bugs in the circuit save are fixed along the way. A block with no title can be saved, because the window asks for a name. And a name you already have, or the 60-circuit limit, is caught before any drills are made.

Why it matters

Coaches refine the same few activities all season. The natural moment to improve a drill is the practice where they improved it. Today the only way to save that is to retype the drill on the Drills tab, and even then next week’s practices still show the old words. This change makes “tonight’s version is the better one” a single save.

Customer impact

Every coach who uses the practice library. It is most useful mid-season, when templates and drills already exist and get tuned week to week. One rule changes: drills used to be copied into practices and never updated. Upcoming practices now follow the drill, and past ones do not, so the practice record a coach looks back on stays true.

Priority

Medium. The template and circuit saves reuse routes that already exist. The drill update is the one new piece of work: it rewrites the team’s upcoming practices on the server, following a pattern the product already uses for staff and equipment tags.

Open for the owner

  • A ruling of “as drawn” on the seven screens.
  • D5–D12, each drawn as recommended. The ones that change most: D7 (templates and circuits holding the drill pick it up too) and D9 (tonight’s station rejoins the drill after Update).

Success criteria

  • A coach improves a drill during a practice and saves it back in one window, without opening the Drills tab.
  • Next week’s practices show the improved drill without anyone touching them, and last week’s practice still reads as it was run.
  • No “You already have a … called …” dead end in any practice save.
  • A circuit save never leaves drills behind for a circuit that was then refused.
Full plan

Save over a practice template, a drill or a circuit

Source: COACH_PRACTICE_SAVE_OVER_PLAN.md. Drawn 2026-10-02; D1–D4 ruled by the owner, D5–D12 ruled as drawn the same day; built on dev 2026-10-02 (§8).

1. Problem

The lineup builder learned this week to save over a template (D13–D15 there). The owner asked for the same on practice plans, drills and circuits. Today each of the three practice saves only creates. A name you already have is refused after the coach presses Save. A drill improved during a practice can only be saved back by retyping it on the Drills tab, and even then no practice that already uses it changes.

2. Findings

F01 — Save as template refuses a name you already have, after the press.The practice page’s Save as template window POSTs a new template. A name matching one of your active templates (capitals and spaces aside) is refused by the unique index with “You already have a template called …”. The window has no way to save over it.
F02 — Save to my drills refuses a name you already have, and updating a drill means retyping it.A station whose name is already one of your drills (the usual case after Edit just for this practice) is refused with “You already have a drill called …”. The only edit path is the drill sheet on the Drills tab.
F03 — A block placed from a circuit has no save door.The block’s door returns nothing when the block came from a circuit (“placed from a circuit — it is one already”). Tonight’s version of a circuit can never go back to the circuit.
F04 — Bug 1: an untitled block cannot be saved as a circuit.The window is titled with a stand-in (“Save “Block 3” to your circuits”), but the save sends the block’s empty title, and the server answers “Give the circuit a name.” When the tick is on, the stations’ drills were already made before that refusal. Retrying fails the same way, because nothing in the window can supply a name.
F05 — Bug 2: the circuit is checked only after its drills are made.With “Also save its stations as drills” ticked, each typed station is created as a drill first, and then the circuit is POSTed. A name you already have, or the 60-circuit limit, refuses the circuit after the drills exist. A retry links those drills rather than duplicating them (the existing design), but a coach who gives up is left with drills from a save that “failed”.
F06 — A drill update never reaches a practice.Rule 3 in the drill library (owner ruling 2026-08-01): “THE DRILL’S WORDS ARE COPIED, NEVER LINKED.” A placed drill copies its words into the plan and keeps the drill’s id only as provenance, so editing the drill changes no practice. The owner revised this on 2026-10-02 (D3): upcoming practices pick up an updated drill, and past ones do not.

3. What the coach sees

  1. Save as template… (practice). The same window, plus “Your templates · tap one to replace it” under the field, newest first. Each row shows blocks · minutes · when it was saved. A matching name shows “You already have a template called this. Saving replaces it.” and the button becomes red Replace “Hitting night”…. The question: “Replace “Hitting night”?” with Now / After (blocks, minutes, tags, saved date), “Practices already started from it keep theirs.”, “This can’t be undone.”, then Replace template and Keep it. Back returns to the field.
  2. Save to my drills… and Save to my circuits… gain a Name field above the tags, filled in with the station’s name or the block’s title (D5). The window’s title becomes “Save to my drills” or “Save to my circuits”. A name matching one of your drills or circuits shows “You already have a drill called this. Saving updates it.”, picks that drill’s tags if you haven’t touched the tags yet (D6), and turns the button into red Update “Partner throwing”….
  3. The drill question shows Now / After (the first line of what you’re doing, coaching points, equipment, tags), then “Upcoming practices pick it up”, which lists them by date and name, and “Past practices keep the version they ran.” Then come “This can’t be undone.”, Update drill and Keep it.
  4. After Update the window closes. Tonight’s station rejoins the drill (D9): it reads “From your drills” with Edit just for this practice, like any placed drill.
  5. A block placed from a circuit shows Save to my circuits… beside its provenance line (D11). The circuit question shows Now / After (stations, minutes, tags) and “Practices that already used it keep theirs. The next time you place it, it’s this version.” (D10)
  6. The Drills tab’s drill sheet says above Save: “Saving updates the 3 upcoming practices that use it. Past practices keep theirs.” The line is absent when none do (D8).

4. The rules

4.1 The name decides

Matching uses the database’s own rule: lower-cased and trimmed, against your active templates, drills or circuits (a retired name can be reused, by the partial unique indexes). A drill name that matches only a club drill saves a new drill of your own, as today. A coach cannot update the club’s set (D12).

4.2 What a save-over replaces

Saved thingReplacedKept
Practice templateThe plan’s shape (blocks, stations, timings, what it’s about) and the tags, which become this practice’s tags (D2)Name (its own spelling), retired state, “started N plans”
Drill, from a stationWhat you’re doing, what you’re watching for, coaching points, setup, equipment (both forms), and tags as picked (D2, D6)Name (its own spelling); how long it usually runs, since a station has no such number
Drill, from a bare blockThe same, plus “usually” from the block’s minutes, as its save does todayName
CircuitThe block’s shape (stations, their setup, points and kit, the rotation’s timing) and tags as picked; people and groups are emptied, as on createName

4.3 What an updated drill reaches (D3, D7)

  • Upcoming practices: this team’s practices that have not started yet. In each one, every station still linked to the drill gets the drill’s words and tag names again. Who runs it, who’s at it, the groups and the just-for-tonight note stay, because those belong to the practice. A linked station is read-only, so nothing the coach did there is lost.
  • Not touched: practices that have started, in any season; any station that was made “just for this practice”; plans in a closed season.
  • Templates and circuits holding the drill (D7, recommended): they pick it up too. They are the next practices, not a record, so leaving them stale would place the old words again next week.
  • Retire and restore reach nothing.

4.4 Circuits and templates do not reach placed copies (D10)

A placed circuit or a started template is edited freely in place: the coach moves stations, sets leads and draws groups for that practice. Nothing records which parts are the coach’s and which came from the library, so rewriting it would undo their work. Only the next placement or start gets the new version. Drill-linked stations inside those copies still pick up drill updates under 4.3.

5. The two bugs (D4)

  • Bug 1: the Name field (D5) replaces the stand-in title. An untitled block opens with an empty field (“What would you call this circuit?”), and Save stays off until a name is typed.
  • Bug 2: before any drill is made, the window checks three things: the name is not empty; a name you already have has already turned the button into Update; and a new circuit at the 60-circuit limit is stopped with “You keep 60 circuits, the most a team can. Update one of yours, or retire one on the Circuits tab.” Only then are the ticked drills created and the circuit saved. A failure after that point, such as a dropped connection, keeps today’s design: the retry links the drills already made.
  • The drill window gets the same limit line at 200 drills, and Save as template gets it at 60 templates. Replace and Update still work at any limit, since they add nothing.

6. Out of scope

  • Pushing a circuit or template update into practices already started from it (D10).
  • A club admin’s edit to a club drill reaching every team’s upcoming practices. The same rule may well apply, but it writes across teams from the admin side, so it gets its own step after this one is walked (D12).
  • Linking a station to a new drill saved from it. Today’s promote copies and leaves the station as typed, and that stays.
  • An undo for Update or Replace.

7. Build notes

  • Practice templates: the existing PATCH on the plan-template route already accepts plan and tagIds, so Replace sends both. The practice-plan read gains each template’s updatedAt for the list and the facts.
  • Drills: the drill PATCH validates a whole drill, so Update sends the full drill. usualMinutes is the drill’s own for a station and the block’s for a bare block. A new GET on the drill route answers the question’s list: upcoming practices (date and name) plus template and circuit counts. It is read when the question opens.
  • The walk: a pure function in the plan module refreshes one plan’s linked stations from a drill, keeping each station’s id, people, groups and note. It is unit-tested, and the server walk and the page both use it. The server walk runs in the same request as the drill PATCH, on the pattern of the staff and equipment tag repoint (rep-practice-plan-tag-repoint.ts): best-effort per row, writing only rows that changed, limited to starts_at > now().
  • The open page converges: after Update, the page relinks tonight’s station (D9), runs the same refresh over its in-memory plan, and marks it dirty. The next autosave therefore writes the new words even if an older save was in flight during the walk. A second tab left open on another upcoming practice could still write old words back on its next edit. The plan PUT is last-write-wins, and the tag repoint lives with the same risk. That is named, not fixed here.
  • Circuits: PATCH on the circuit route (block, tagIds). The door on a placed block is the existing promote door with its circuit guard removed.
  • Dictionary: rep_team_events.practice_plan says “Written only by updateRepTeamEventPracticePlan”. That is already untrue (the tag repoint writes it) and becomes less true. Update it to name both walks, and revise rule 3 in the drill library’s header to the D3 wording.
  • Shared window: the lineup’s replace window and these three differ in body. The confirm view (Back, question, Now / After, warning, two buttons) is one pattern, and one small shared component should draw it rather than four copies.
  • Checks: verify:changed; unit tests for the refresh walk (kept fields, unlinked stations untouched, past untouched) and the name match; the layout sweep on the practice plan screen; the spelling gate. Help: the practice-plan articles learn save over, Update, and the upcoming-practices rule.
