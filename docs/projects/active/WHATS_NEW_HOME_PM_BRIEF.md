# What's New Gets a Home — PM Brief

**What it is.** The "new" dot comes off Help. Release news gets its own quiet spot, and only releases the owner
chooses to announce light anything up.

**Why it matters.** Today the dot sits on Help nearly all the time, so it tells nobody anything, and people looking for
help meet a notification instead. Help should be a plain door. When a release really changes someone's week, the
owner wants that to stand out, which only works if most releases stay quiet.

**What people see.**
- Help: a plain row, no dot, on every desktop sidebar. Nothing about where it leads changes.
- What's new: a row at the top of the account menu on desktop, and a row next to Account in the phone More sheet.
  A small "New" tag shows on it only while an announced release is unread on that device.
- Overview (club admin): one soft line under the title when a release has been announced, with a link and an X.
  The X, or opening What's new, clears it on that device. One line at a time, never stacked.
- Coaches get the menu row and phone row at once. Their Overview note comes in a second step.

**Who decides.** At each release the release agent proposes announce or don't announce, with its reason and the one
line of text, and the owner answers yes or no. Not announcing is the normal answer. Past releases show nothing on
day one.

**Priority.** Medium. Small build, no data changes, high daily visibility.

**Success looks like.**
- No dot anywhere in the product by default.
- A release the owner announces is noticed by admins within a day or two (the note is dismissed or opened).
- Fewer "what is that dot" questions; Help clicks come from people who need help.

**Tradeoffs.** The note pushes the Overview down about 55px while it shows. Opening What's new still goes to the
public page in a new tab; an in-app release page is a separate decision. Someone has to answer yes or no at each
release, which takes a few seconds.
