## 0. What this is

The owner asked for the practice workflow (schedule → plan → print → run → after) to be re-evaluated the way Skills & Goals was:
a walk of every screen as built (eleven stations, five standing-back questions), then **one proposal tab per stage, ruled and built one
at a time**, each stage drawn before/after at true size in the portal's own materials with clickable markers and Build-as-drawn /
Change-it / Not-now decisions. The walk's headline is a SHAPE, not a list of items: the plan maker is a form where a document should
be (a three-block practice is 6,627px and 59 inputs on desktop; the printed run sheet already has the shape the screen lacks).

**Owner direction, 2026-09-14 (binding for every stage):**
- **Practice plans is the hub for three things — the season's practices, plan templates and the drill library.** Skills & Goals is
  metrics, player goals and sessions only, linked to a practice only by *when a session happened*.
- **Tabs, not a dashboard and not stacked headers.** Practices · Templates · Drills; Practices is the landing. No overview tab, no
  tile row: the next-practice card and the "Needs a plan" chip are the room's whole state.
- **The nav entry keeps its name, "Practice plans."** Nav gates are keyed by label; Lineups is named for the instrument too.

### 6.4 The D4 revision — why the drawn frame was not what got ruled

Drawn on 15 September, D4 read the same way every other "open in place" moment on this sheet reads: a station column widens where it sits, its siblings folding to quiet heads beside it. Reviewing the built draw, the owner asked why a station couldn't just open as a modal instead, given how much of the card's height was going unused beside two collapsed columns. The frame's own justification — "a row opens in place so a coach can see where they are in the sequence" — was checked against the actual claim and did not survive it: that reasoning is true of a BLOCK, which really does run before and after its neighbours in time, and false of a STATION, which merely shares a clock with the stations beside it and has no other relationship to them. Once the one reason for keeping the layout in-line was gone, the modal was strictly better for a card this deep (nine fields): no dead columns, no inline scroll competing with the page's own scroll, full width to work in. The one thing a modal owes back is "what else is happening tonight," which the sheet was answering through the layout — the fix is a footer stepper doing the same job the fundraiser drive drawer's own "‹ 1 of 2 drives · Bottle drive ›" control already does, so this is a second application of an existing pattern, not a new one. **Ruled: build the modal (with the stepper), not the widening column** — the hub's "3 · Stations and the rotation" tab carries both frames, the superseded inline draw and the modal that replaces it, so the record shows what changed and why.
