The same Stripe event twice, and out of order, changes nothing twice

Written 2026-10-28. Stripe sometimes delivers the same event again, and does not promise to deliver events in order. This walk makes Stripe do exactly that on purpose and checks that nothing doubles: no second email, no second record, no second receipt number.

What this walk is for

This walk resends events that earlier walks already produced. In Stripe’s dashboard, every delivered event has a Resend button; pressing it sends the very same event to our site again, exactly as Stripe does on its own when it retries. Nothing is bought or paid in this walk. What you are testing is that the site recognises “I have already done this” and stays still.

The site protects itself in two different ways, and the walk looks at both:

  • Team payments and club account changes (the two “Dev: club…” destinations) keep a list of every event they have handled. A repeated event is answered “already done” and skipped outright (Parts C and E).
  • Plan purchases and subscriptions (the Billing destination) keep no such list. Each step is written so that doing it twice is harmless: the second run finds the portal or club already exists, and it sends no second welcome email (Part B).
  • Out of order (Part D) is the open question. The Billing side writes what the event says. This walk shows what an older subscription event does when it arrives after a newer one, so you can rule on whether that is acceptable.

What “no change” looks like here is always a relationship, not a figure: the same count of emails in Resend before and after, the same receipt number on the desk, the pay page and the email, the same lines in the club’s Story.

It passes when
  • Resending the plan-purchase event twice leaves the Resend dashboard with the same number of welcome emails, the platform-admin Story with the same number of “Bought” lines, and the coach’s portal unchanged.
  • Resending a team’s deposit payment event leaves the receipt email count at one, the desk with the same payment rows and the same receipt number, and the team’s balance unchanged.
  • Part D is answered: you have ticked what the club’s billing screen did when the older event arrived, and what you want the product to do about it. That part is an observation, not a pass/fail.
  • Every delivery line in the three Stripe destinations during the walk’s window reads 200.

Before you start

Setup, not checked. Keep this page private: it holds dev passwords.

Where
The dev site https://dev.fieldlogichq.ca, plus two other tabs: the Stripe dashboard (the sandbox “FieldLogicHQ sandbox”) and the Resend dashboard › Emails (every message the site sends is listed there, with subject and recipient).
Webhooks
Stripe dashboard › Workbench › Webhooks. Three destinations: Billing (plan purchases and subscriptions), Dev: club payments (team deposits) and Dev: club account events (payouts account changes). Each has an Event deliveries tab. Click an event there and a Resend button appears. Stripe’s own documentation says Resend works for 15 days after the event, so every event you use must be less than 15 days old.
If there is no Resend button
Stripe’s command-line tool does the same job: in a terminal, C:\tools\stripe\stripe.exe events resend evt_… --webhook-endpoint=we_… (the evt_ id is on the event’s page, the endpoint id is on the destination’s page; the command line works for 30 days). It must be logged in to the sandbox first. If it is not, stop and tell me.
What a resend does
Stripe sends the same event again and adds a new delivery line under the event, with the status code our site answered. A healthy answer is 200. Resending leaves nothing behind in the product, only extra delivery lines in Stripe’s history, so there is nothing to put back (except in Part D, which says so).
Emails
The coach from Walk 1 and the team’s payer from Walk 9 each used a plus-address inbox. You need access to both inboxes' messages in the Resend dashboard (search the Emails list by recipient). Real mail sometimes takes up to 2 minutes; always wait and refresh before you count.
Figures that may drift
Plan names on the pricing page, and the “New subscriptions” count on Business numbers if someone else buys something during the walk. Counts that must match are always compared with your own before-figure, never with a number written here.

Stop check

This walk needs three things from earlier walks. Part A shows each one and tells you to stop if it is missing. A Premium purchase from Walk 1 (less than 15 days old), a team’s deposit paid by card through Walk 9 (or 8) on Stripe Walk Invitational (less than 15 days old), and, for the optional Part D, a Tournament Plus club from Walk 2 that still has its real subscription. If you did the earlier walks more than 15 days ago, Stripe will not let you resend those events: redo the purchase or the payment first, then come back.
