# Notification census: every kind, sorted by how its body reads

Source of truth for the kinds: `NotificationEventType` / `NOTIFICATION_EVENT_LABELS` in `lib/notification-labels.ts` (81 kinds). Bodies are traced to the code that builds them. Examples keep the template wording verbatim; the values are made up. "⏎" marks a line break the template itself writes. The opened-notice reader (`components/notifications/NotificationMessage.tsx`) renders the body with `white-space: pre-line`, so a body that already has `\n` shows its breaks.

## Counts

| Group | Meaning | Kinds |
|---|---|---|
| Done | already laid out as labelled rows | 1 |
| C | a list inside the sentence | 6 |
| B | 3+ distinct facts | 22 |
| X | user-typed text, must stay as-is | 4 |
| A | one fact or one short sentence | 42 |
| dead | no sender | 6 |
| Total | | 81 |

Two kinds are split across groups by variant (the group shown is the heavier variant; the lighter one is noted in the row): `club_hand_back_answered` (C when accepted, B when declined) and `club_season_changed` (B when a season starts, A when closed or reopened).

Reading rules used: a row is B when the BODY carries 3 or more facts a reader would look for separately; facts that only the TITLE carries are noted in the reason but do not count. A is a body with 1 or 2 facts, even when the sentence is long. "Recipient" is taken from the sender code.

## Surprises worth a decision

- **`club_schedule_league_changes` already puts line breaks in its body** (`\n\n`, then one `\n` per game). It is the only kind whose stored body contains newlines. The practice-plan and availability-reminder messages also have newlines, but those are the push/email body; the bell bodies for those kinds are single lines.
- **`family_availability_response` already stores structured facts** (`metadata.bundle`: items with child, answer, prior answer, parent, event, count) and re-writes title and body when more answers fold into the same unread notice. It is the closest kind to `house_league_time_given`: rows need no new storage.
- **Several kinds are built in more than one place or in several variants with different wording:**
  - `registration_new` (four routes), `registration_status_changed` (single and bulk), `payment_received` (by hand, bulk, team online, house-league online), `house_league_registration_new` (public form vs admin entry), `card_refund_failed` (team, house-league child, bank-debit variants at five sites), `online_payment_not_recorded` (four builds), `card_disputed` (answerer vs desk, dispute vs inquiry).
  - Hand-back bells: asked, withdrawn, accepted and declined each have an “on time” and a “late ask” twin with different wording (`lib/club-hand-back-words.ts:260-283` vs `:339-358`).
  - `club_schedule_review` has up to four audience variants (head coach vs staff, with or without the bill) built in one place.
  - `team_coach_registered` carries two wordings (registered vs waitlisted).
  - `team_coach_game_changed` has a single-game and a several-games form.
- **Title carries facts the body doesn't.** Several money kinds put the amount and the team only in the title (`club_money_received`, `club_payment_handed_off`, `team_coach_payment_reminder`). If the reader gets rows, deciding whether rows draw the title’s facts too is a prerequisite.
- **`score_submitted` names nobody and no score:** the body is just “Submitted by <email>”; the game and result are only reachable through the link.
- **`club_schedule_changes` and `club_schedule_final` carry only a count** ("3 changes", "8 practices"); the actual slots are in the email.
- **Chat kinds are sent but never reach the bell:** `chat_message` and `chat_mention` are suppressed from the bell (category `talk`) and chat is paused (`CHAT_PAUSED = true`, `lib/chat-pause.ts:27`).
- **All ten `team_coach_*` kinds bypass `notify()`:** they are inserted straight into the `notifications` table (`lib/team-coach-notices.ts:38`, via `notifyTeamCoaches`; the invitation at `:172-182` with its own link `/discover`), so they are bell-only. `team_coach_registered` and `team_coach_game_changed` come out of shared builders with variants.
- **Kinds that are not X but carry typed text:** `club_money_undone`, `club_request_declined`, `club_request_reversed`, `team_request_filed`, `club_schedule_reply`, `house_league_withdraw_request`, `club_hand_back_answered` (declined variant). A rows layout must keep the typed part as a plain quoted line.
- **No kind has an empty body**; `team_coach_accepted` and `team_coach_declined` bodies are the shortest (tournament name only). Optional bodies exist in the type (`body?: string`) but every sender sets one.
- **The dead kinds still have labels, descriptions and category entries**, so old bell rows still render; none can be created today.
- **Some examples use values I made up** where the template takes a free-form input (a house-league payment’s description, an allocation’s name, the request description); all sentence wording is verbatim from the templates.
