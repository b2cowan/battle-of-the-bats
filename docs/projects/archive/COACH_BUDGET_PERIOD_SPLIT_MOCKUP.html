Splitting a budget line by period

A working mockup of the Add / Edit Budget Line form. Three changes: the save warning becomes impossible to miss, period labels stop being mandatory, and a coach says how the line is split — by month, by quarter, or by exact dates — so an annual budget stops costing twelve trips through a date picker.

New Restyled Unchanged — every element in the proposed form carries one of these.

The warning sits inside the part of the form that scrolls, just above the buttons. When a coach presses Save Changes with the period rows on screen, the page doesn't move and the message never comes into view — so the button reads as broken. Scroll the panel below to find it.

Proposed form

Fully interactive. Two steps inside the breakdown: pick how this line is split, then add periods one at a time exactly as today. Each row carries its own period picker, so what a row is stays on screen no matter what gets typed in the label.

03

Changed after each look

Fourth round

  • The selected mode chip is a tint, not a filled olive button. The warm portal's standing rule is that olive is a text, border and tint accent only — a filled olive button reads muddy on cream and competes with the real lime action. The chip now matches the $ / % segment directly above it, which is the same kind of control and was already doing it correctly.

Third round

  • Changing the split mode now starts the periods over. The previous version tried to convert one shape into another, which only works when the shapes correspond — and they don't. Twelve months mapped onto four quarters piled three rows into each quarter, and switching back produced three Januaries, three Aprils and so on.
  • The reset is recoverable. Switching away from a split that had periods in it leaves the same Undo the other bulk actions do, and undoing puts back both the periods and the mode they belonged to. Switching away from an untouched single row says nothing, because nothing was lost.

Second round

  • A new line starts with one empty period, never twelve. The scenario buttons above load finished budgets to show the shape; the first one, New line, is what a coach actually gets on ticking “Split by period”. One row rather than none, so the shape of a period — picker, label, amount — is visible without having to click to find out.
  • “Clear all periods” joins the add bar once there are two or more rows, so rebuilding doesn't mean clicking × twelve times.
  • Bulk actions can be undone. Fill the season or clear the lot and a quiet strip appears offering Undo. It's there instead of a confirmation dialog — the coach isn't stopped to answer a question they'll almost always say yes to, and the accident is still one click from being repaired. Doing anything else retires the offer.

First round

  • The wall of month chips is gone. Periods are added one at a time with “Add period”, the same gesture as today — the mode just decides what kind of picker each row gets.
  • Every row carries its own visible period picker. Previously the month lived only in the label's grey placeholder text, so typing a label hid it and row order became the only clue. Now the month is a control that never goes away.
  • The picker sits first, the optional label second. Scanning down a twelve-row budget gives you a clean column of months on the left edge.
  • Column headings appear above the rows so “optional” is stated once, in writing, rather than implied by an empty box.
  • The form is a touch wider — matching the event form — to fit three controls per row without crushing them.
04

What each mode asks for

All four produce exactly the same thing underneath — a set of named, dated amounts — so Budget vs. Actual, the month grid and player installments keep working untouched. The mode is only about what the coach is asked to do. Changing it starts the split over — it's a decision about how the line works, not a display setting — with an Undo offered whenever there was anything to lose.

Undated periods are allowed, with a warning, not a block. A period with no date can't be placed on a calendar, so Budget vs. Actual lumps it in with the last one. The form says so on the row. That's information the coach needs — it isn't a reason to stop them saving.
05

The three changes, stated plainly

A save that fails does something visible

The form jumps to the first problem, marks the field, and shows a count beside the button that stays visible however far the form is scrolled.

Clicking the count jumps to the problem again. No second dialog — a dialog would cost an extra dismissal and still wouldn't say which row was wrong.

Labels stop being mandatory

A period that has a month, quarter or date names itself, and that name is shown greyed in the label box until the coach types over it. The period's identity lives in its own picker, so it stays visible either way.

With no date and no name, periods fall back to “Period 1”, “Period 2”. Nothing about naming can block a save any more.

Only amounts can block a save

Every period needs an amount, and the amounts have to add up to the line total. Those are real accounting constraints, and the running total already shows them live.

Everything else — names, dates, notes — is either derived or advisory.

06

What else this touches

  • Budget vs. Actual — unaffected. It reads names and dates, and now gets better ones: real month names instead of whatever a coach typed at 11pm.
  • The month grid — improves. Month mode produces periods that land cleanly in month columns by construction, which is what the grid wants anyway.
  • Player installments — unaffected. Generating dues still reads the plan the same way.
  • Spreadsheet import — worth a look in the same pass. An imported budget arrives month-shaped more often than not, so it should land in month mode rather than as loose dated rows.
  • The org-side budget planner — stores periods the same way and probably carries the same required-label friction. Not yet confirmed; worth checking before committing to it.
  • Existing budget lines — untouched. A line saved before this change opens in whichever mode matches what it already holds.
07

Decisions needed before build

  • Default mode for a new line. Mockup remembers the coach's last choice on that team. The alternative is defaulting by category — tournaments to dates, ice time to months.
  • One starting row, or none at all. The mockup opens a new split with a single empty period, on the grounds that it shows what a period looks like without a click. Starting completely empty is the cleaner-looking option and just as defensible.
  • Which month the first row lands on. January today, because that's the start of the season year on record. If your clubs' seasons start in September this will be wrong every time — but fixing it properly means recording a season start month, which is a bigger change than this one.
  • Season span. The picker offers the season year and the one after it, so a season crossing New Year works. Whether the first row should default to January or to the month the season starts is a real question — the platform doesn't currently record a season start month.
  • Quarters. Calendar quarters in the mockup. Nothing stops these being season quarters if that's how your clubs talk.
  • Repeat months. Two rows can sit in the same month — legitimate for two payments, but also an easy slip. Silent, or a quiet note on the row?
  • Months → specific dates is the one switch that could survive. Roughing a line out by month and then pinning exact due dates is a real habit, and each month has an obvious date to become. Everything else resets; carving out this one case would be genuinely useful but breaks the “a mode change starts over” rule the rest of the form now follows.
  • The blocking dialog. This mockup deliberately doesn't use one. If you'd still prefer a modal warning, it drops in without disturbing anything else here.
