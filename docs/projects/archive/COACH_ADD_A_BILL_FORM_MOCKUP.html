1What the owner judged wrong

1Grey-on-grey nesting

Plain inputs wear the warm paper ground; the picker and the date field render white, rounder, fainter-edged. One row holds both families side by side.

5The three decisions this draws

D1 — One surface, one header line.

The quiet olive tint is the schedule's surface; the white inner card dissolves. The header collapses to one line — the title left, Repeat monthly and + Add right, keeping their button chrome and their pairing; only the empty band between the two old header rows goes. The count sits under it when there is genuinely more than one payment. On the phone, each installment keeps a card of its own (that grouping is real work down there), now white on the tint instead of tint on white on tint.

D2 — Column headings, the budget sheet's own idiom.

A Due date / Amount ($) headings row above the rows at desktop — the same device the budget sheet renders over this exact row shape, which this editor borrowed without. On one row the headings quietly double as the row's labels, so the browser's bare yyyy-mm-dd finally has a name over it — and the number gutter doesn't exist yet, so the row fills the section's full width, appearing only once there are #s to hold. At phone width the headings stand down and the existing stacked per-row labels carry on, unchanged.

D3 — One grounds story: every field wears paper.

The picker and the date field stop rendering white and take the portal's standard field ground — paper fill, the stronger hairline, 6px radius — the ground Description and Amount already wear. One family of inputs on one form; required-ness is carried by the plain asterisk alone, never by which component a field happens to be built from.

What this pass never touches: every word, the field order, the picker-before-description rule, the Repeat monthly / + Add pairing, the reconcile sentence, the Auto badges, the More fold, the footer-pinned consequence and the plain "Save" — all settled in the §119 fold. The one-line header is the single structural nudge this sheet asks approval for, and it changes placement only — both tools keep their chrome and their pairing. Build discipline: all restyles land as variant classes scoped to this editor and this form; the budget sheet and the dues sheet render byte-identical before/after (screenshot-proven), and the reverted desktop-label override is not re-attempted — the headings row is a new element, not a CSS force. Verification is Playwright against the live form at 1440 and 390.
