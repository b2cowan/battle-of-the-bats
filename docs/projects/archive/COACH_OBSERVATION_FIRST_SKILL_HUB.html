1

The button is switched off, and nothing shows it today

“Record an observation” is switched off whenever the team’s Metrics hold no active skill. A test like a sprint doesn’t count, because an observation is always about a skill, and a retired skill doesn’t count either. The product’s standard button has no switched-off look at all, so it looks exactly like “+ Add goal” beside it and even lights up under the mouse. A click does nothing.

Production matches the current code here: nothing in these files has changed since the 09-23 promote.

2

The only explanation is a hover tooltip today

“Define a skill in Metrics first” appears only while a mouse rests on the button. A phone has no hover and a keyboard never shows it. Even a coach who does see it is sent away: to the Metrics tab, to set up a skill, then back through the roster to find the player again.

A quick check you can do: hover the button on Milton Bats U13 Purple. If this is the cause, the tooltip appears, and Metrics lists tests but no skill.

4

“+ New skill…” under the Skill field new

This mirrors “+ New test…” on Record a result, which has always been live. The Skill field still says “No skill defined yet”, as it does today, and the link under it is the way forward. It shows on every new observation, not only when the list is empty, so a coach can add a second skill mid-thought the same way.

It does not show when editing a saved observation, because the skill is that record’s identity. It also does not show from a session’s grid, where the session has already fixed the skill.

The wording is new. The test link says “defines a whole test, as everywhere”, but “+ New skill…” exists nowhere else yet, so this one says where the skill ends up: in Metrics.

5

Typing first is fine; saving waits for a skill restyled

A coach often has the sentence in mind before they think about the Metrics library, so the fields work straight away. Save observation stays greyed out until a skill is picked. The form’s own buttons do have a switched-off look, unlike the toolbar button. Nothing typed is lost on the way to “+ New skill…” and back.

Nothing else on the screen moves: the toolbar keeps its three buttons in the same order, and the tab reads exactly as it did before the tap.

6

The setup form arrives already set to Skill restyled

This is the same form Metrics uses to define a metric, opened on top of the observation the way “+ New test…” opens it on top of Record a result. From this door the Kind is shown as a fact rather than a choice, and the title reads “Define a skill” instead of “Define a metric”. An observation can only be about a skill, and a door that has answered a question shouldn’t ask it again, which is the rule the observation form was built on. If Kind stayed a choice, a coach could define a test here and be left with no skill.

From Metrics and the session planner it is unchanged. Built one step further than drawn: Record a result’s “+ New test…” now opens as “Define a test” the same way, because a skill defined there could never sit in the Test list it returns to (see D3).

7

Back in the form, the new skill is picked new

After Save definition, the setup form closes and the coach lands back in the observation with the new skill in the Skill field. If they listed descriptors, the Descriptor choice appears, as it does for any skill that has them. The sentence they typed is still there, and Save observation is now live.

The skill is in Metrics like any other: the session planner, the goal’s own button and every other player’s page offer it from now on.

On a phone, give the link a thumb-sized tap area your call · recommend yes

The phone form is today’s: a back arrow instead of Cancel, and the save docked at the bottom at 56px. The only addition is the link. As a bare text link it is only as tall as its line of text, well under the portal’s 44px floor, and it is a coach’s only way forward when there is no skill yet. Built: 44px tall on a phone (measured 76 × 44 at 390). Recommendation: give it a 44px tap area at phone width (the dashed box). Its twin, “+ New test…” on Record a result, has the same problem today, and the two links share one style, so fixing one fixes both.

The alternative: leave both as text links to match today, and take the tap floor up with the dialog-footer tap-floor ruling that is still open.

Open this page on your phone to judge the size. The frames are drawn at true width.

9

Once the skill exists, the phone form works as it already does unchanged

At phone width a skill’s descriptors are 56px rows, the text box becomes “Anything to add?”, and the save docks at the foot. That is phone stage 4, untouched. It is drawn here so you can follow the whole path on the device: no skill, then + New skill…, then back in the form with the answers ready.

The root cause is broader than this screen. The platform’s standard button has no switched-off look at all, in any portal. Product-manager brief

Record an observation, before the team has a skill

Proposed 2026-09-28 · small fix to a defect reported on production

What changes for the coach

  • On a player’s Skills & Goals tab, Record an observation always opens its form: on the toolbar, and inside an open goal.
  • If the team hasn’t set up a skill yet, the form says so and offers + New skill… under the Skill field. That opens the same skill setup Metrics uses, on top of the form. Saving it brings the coach straight back with the new skill picked and anything they had typed still there.
  • + New skill… is offered on every new observation, so a coach can add another skill mid-thought the same way.
  • On a phone, the link gets a thumb-sized tap area, and so does its twin “+ New test…” (if ruled in, D4).

Who it affects

Coaches who can record observations today: those with the Development permission plus Internal notes. Nobody gains or loses access. Creating a skill needs the Development permission, and every coach who sees this button already has it, so the link never appears for someone it would refuse.

Why it matters

Today the button looks live and does nothing when the team has no skill. The only explanation is a hover tooltip that phones never show. A coach who clicks it assumes the feature is broken, and one who hovers is sent to another tab and has to find the player again. You found it on production.

Customer impact

It affects every team whose Metrics hold no active skill: teams that have only set up tests, and teams that haven’t opened Metrics yet. For most coaches this is their first try at observations, so it is the feature’s first impression.

Priority

Small and self-contained: a visible defect on production, no database change, one screen and the two forms it opens. It fits alongside current work.

Success criteria

  • A coach on a team with no skills goes from a player’s page to a saved observation without leaving the page.
  • No switched-off button remains on the Skills & Goals tab.
  • A skill made this way appears in Metrics and in the session planner like any other.
Full plan

Record an observation, before the team has a skill: implementation plan

Drafted 2026-09-28 · waiting on D1–D5 · no migration

What the code does today

  • Both “Record an observation” doors on the player’s Skills & Goals section (the toolbar and an open goal) are disabled when the team has no active skill (kind = skill and active). The only explanation is a title tooltip: “Define a skill in Metrics first”. Source: components/coaches/PlayerDevelopmentSection.tsx, the toolbar door and the goal-row door.
  • The global .btn rule in app/globals.css has no :disabled style, so a disabled btn btn-ghost renders identically to an enabled one and still takes the hover fill.
  • The twin, Record a result, is never disabled. RecordResultSheet shows “+ New test…” under the Test select, which stacks MetricDefinitionSheet over the form (stage 1’s precedent, B8); on save it selects the new test and hands it to the host (onTypeDefined).
  • Production matches the current code for these files: no change since the 09-23 promote.
  • The reporting team’s skill list was not read directly in this session. The owner can confirm the cause by hovering the button.

Scope

  1. The two doors (D1). In PlayerDevelopmentSection, remove disabled and title from the toolbar door and the goal-row door.
  2. The observation form (D1, D2). RecordObservationDialog gains an optional define path: on a new, un-fixed observation (no editing, no fixed), a “+ New skill…” link under the Skill select, in the result sheet’s link style. It opens MetricDefinitionSheet stacked, with the kind fixed to skill. On save: select the new skill, clear the answer, and hand it to the host. It needs orgSlug, teamId and an onSkillDefined callback; hosts that pass nothing draw no link. The typed sentence survives, because the form stays mounted beneath the stacked sheet.
  3. The setup form (D3). MetricDefinitionSheet gains an optional kind prop. On a new definition it fixes the kind: Kind renders as a fact, and the title reads “Define a skill” or “Define a test”. Every existing caller passes nothing and is unchanged.
  4. The host. The player section adds the new skill to the library it holds, the same move typeDefined already makes for a test, so the skill list and the goal door see it at once.
  5. Phone tap area (D4, if ruled in). The shared link class gets a 44px tap area at ≤640px. That covers both “+ New skill…” and “+ New test…”.
  6. Help. One sentence in the Skills & Goals article: with no skill yet, “+ New skill…” in the form defines one.
Where the link does not appear: editing a saved observation (the skill is the record’s identity); a session’s grid (the chip fixes the skill); the Notes tab’s Edit (always editing). The session page and the Notes tab pass no define props, so nothing changes there.

Out of scope

  • The product-wide switched-off look (D5). About a hundred disabled global buttons, most transient while saving. That needs its own design ruling, and it overlaps the Admin Design Continuity work in flight.
  • Restoring a retired skill from the form. Metrics does that, as today.

Build notes (2026-09-28)

  • One shared door, useNewMetricDoor. “+ New test…” and “+ New skill…” come from one hook. It returns the link (for inside the host’s form) and the stacked definition sheet (for beside the host’s shell), with the wording, the tap floor (44px at ≤768) and the kind-fixing in one place. The link style moved out of PlayerDevelopment.module.css’s .defineLink. /simplify 2026-09-28 widened it from a shared link to the whole door, because the open, stack, pick and hand-back wiring was duplicated in both hosts and had already drifted (only one cleared a stale error).
  • MetricDefinitionSheet takes kind. A new definition from a record sheet’s door is fixed to that kind: Kind reads as a fact, the title is “Define a skill” or “Define a test”, and the unsaved-changes baseline starts from the same blank, so an untouched sheet cancels without asking.
  • Beyond the drawing (D3 applied to the twin): Record a result passes kind="test". Left a choice, a skill defined from “+ New test…” came back to a Test select that cannot hold it, with Save switched off and no reason given.
  • The Skill and Test fields are a div with a label htmlFor, no longer a wrapping <label>. Inside the label, the link’s whole sentence had become part of the select’s accessible name.
  • The setup sheet mounts beside the record sheet, never inside its form. QuestionShell renders in place, so a sheet inside the form would be a form inside a form, and its submit would bubble into the observation’s save.
  • The help sentence is left for /docs (the article carries search keywords to keep in step).

This matches Record a result, which has never been switched off. “+ New test…” is always there on a new result. A link that appears only when the list is empty would teach the coach it’s an error path rather than a normal way to add a skill.
