## Goal

Make the close of a season a **moment** instead of a lockout: a coach whose season has been marked complete keeps a way into that team (read-only), lands on a celebratory **Season's End** screen with a shareable **Season Wrapped** card, gets an honest **"you're probably done"** nudge while the season is winding down, and reads truthful rollover copy about what carries and what stays.

## Ground truth (verified by direct code read + 3-agent sweep, 2026-07-28)

### The lockout (P0 #1) — confirmed, both models

- `getCoachingAssignmentsForUser` (`lib/db.ts:4024-4027`) filters assignment rows to program-year status `draft|active`. `getActiveRepProgramYear` (`lib/db.ts:4064-4076`) carries the **same filter independently** — the current-year resolution is duplicated, not shared.
- Zero assignments → `app/[orgSlug]/coaches/layout.tsx:62-87` renders the "Not assigned to any teams" wall — the entire portal for that org.
- `lib/coach-rep-phase.ts:56`: the `result` (afterglow) phase fires **only** on `completed|archived`. The "That's a wrap" card (`teams/[teamId]/page.tsx:1041-1060`) is therefore **unreachable** — gated on exactly the state that removes access to the page it renders on. Review claim confirmed verbatim.
- **Club-owned teams:** admin closes a season at `app/[orgSlug]/admin/rep-teams/teams/[teamId]/program-years/[yearId]/page.tsx` — the "Mark Completed" button fires the PATCH **with no confirmation dialog and no mention of coach impact** (route: `app/api/admin/rep-teams/teams/[teamId]/program-years/[yearId]/route.ts`, transitions `draft→active→completed→archived`). Creating the next year is a separate manual admin step that **does not carry coaches** (`program-years/route.ts` POST inserts a bare draft row; coaches re-added one at a time). So club coaches (head + assistants) are stranded from "Mark Completed" until the admin manually re-adds them to a new year. This is the full P0 scenario.
- **Standalone (team_workspace) teams:** only the head coach can close a season, and only via "Start next season" (`seasons/route.ts:39-49` gate; `lib/rep-season-rollover.ts`), which creates the new **active** year and copies all coaches + active roster FIRST, then marks the old year `completed` (rollover.ts:395-401). So a standalone coach is **never locked out** — but the closed season vanishes from their portal identically, so the wrap-up moment never renders for them either. The admin rep-teams namespace is unreachable for team_workspace orgs by construction (no `module_rep_teams` entitlement + layout redirect), so nobody can close a standalone season out from under its coach.
- **Assistants:** `rep_team_coaches` is per-program-year (`UNIQUE (program_year_id, user_id)`). The standalone rollover copies all coach rows; the admin path copies none.

### Why "just widen the status filter" is unsafe (the write-path inventory)

- `resolveCoachContext` (duplicated ~43-49 routes) resolves the program year **twice**: via the assignment lookup AND via `getActiveRepProgramYear`. If the assignment filter were widened: a team with only a closed year 404s by accident ("No active program year"); a team with a closed year **and** a new open year silently resolves every write to the **new** year — a coach editing from a closed-season screen would corrupt the current season.
- **No coach route or write function checks program-year status before writing.** "Previous season goes read-only" (the shipped Phase-5 promise) is enforced solely by invisibility — `UPDATE ... status='completed'` plus the two filters. There is no trigger, no RLS rule, no app-layer guard.
- **Unguarded ID-scoped write holes exist today** (protected only by team-level invisibility): development goals/measurables POST routes never resolve a program year at all and never check the target roster row's year; `roster/[playerId]` PATCH checks team/org but not `player.programYearId === programYear.id`; `awards/[awardId]` DELETE deletes by team only (any past season's award deletable whenever *some* year is open — this one is arguably intended, awards are team history; see 1.6).
- **Conclusion (architectural):** closed seasons get their own explicit read-only surface with an assignment check scoped to THAT year; the general active-season gate is **not** widened. Riders close the year-scoping holes.

## Phases

### Phase 1 — Never locked out (P0 #1): the closed-season access model

- [ ] **1.1 Closed assignments become visible, explicitly and separately.** `getCoachingAssignmentsForUser` gains a companion (new function or an options flag — decide at build; do NOT change the default return shape 119 call sites depend on) returning assignments on `completed|archived` years, flagged `seasonClosed: true` + `programYearStatus`. The assignments API (`/api/coaches/[orgSlug]/assignments`) returns them as a separate `closedAssignments` array so no existing consumer's semantics change silently.
- [ ] **1.2 The layout wall only renders when the coach has NOTHING.** `app/[orgSlug]/coaches/layout.tsx`: if active assignments are empty but closed ones exist, render the normal portal shell scoped to the closed-season experience (1.3) instead of the wall. The wall's copy also gains one honest line for the true-zero case (unchanged behavior otherwise).
- [ ] **1.3 The Season's End surface (per D1 — recommended: wrap-up + read-only history, not a full read-only portal).** A closed team's landing = a dedicated **Season's End** page: the Season Wrapped card (Phase 2), the final record, and doorways to what remains readable — the Insights **results archive** (already season-switchable) and season history. Sidebar/bottom-nav for a closed team collapses to this reduced set (Overview→Season's End · Insights archive · Settings-lite) — no dead nav into 404ing sections, no write affordances anywhere.
  - **Path to the future:** standalone head coach → **Start next season** CTA (existing modal). Club coach → honest copy: "Seasons are managed by {org}. When you're on next season's roster of coaches, the team reappears here automatically." Assistants (both models) → same read-only view, no season CTA.
  - **Team switcher + My Teams hub:** closed teams appear in a quiet "Season complete" group instead of vanishing (labeled chip, e.g. "2025–26 · Complete"). A coach with an active new year AND a closed old year on the same team sees ONE team entry (the active year) — the closed year is reachable via Insights, not a duplicate switcher row.
- [ ] **1.4 Read-only API surface for closed seasons.** A closed-season context resolver (new, small): requires an assignment row on **that specific program year** (any status) — never `getActiveRepProgramYear`. Serves: the Wrapped payload (2.2), the Season's End summary, and the existing history/results archive (already safe — verify its gate allows a coach whose ONLY year is closed; today `/history` resolves through the active-year context and would 404 — fix so history is reachable in the closed state). GET-only; money data behind the same money-capability redaction as today.
- [ ] **1.5 Admin "Mark Completed" gets a confirmation that tells the truth (D2).** The admin program-year page's transition button gains a confirm dialog (admin-side styling): completing locks the season to read-only for coaches, they keep the wrap-up + history view, and the next season's coach list starts empty until re-added. No email/notification in this batch (see Out of scope).
- [ ] **1.6 Defense-in-depth riders (close the year-scoping holes found in verification).** (a) `roster/[playerId]` PATCH: require `player.programYearId === programYear.id`. (b) development goals/measurables POST routes: resolve the active year and require the target roster row belongs to it (the `carry` route keeps its deliberate cross-year read). ### Phase 2 — Season Wrapped (Wow #7)

- [ ] **2.1 One canonical season-summary computation — `lib/rep-season-wrapped.ts` (new, pure, unit-tested).** Input: a season's events, attendance reliability, awards+players, lineup analytics. Output: final record (canonical rule: league + tournament games, scrimmages excluded — matching the Overview result card the coach already sees; build-time check on live `event_type` values first), longest win streak, closest game (min decided margin, with opponent + score + date), team attendance rate (games bucket, known-responses denominator), top award-winner (count + award names; ties honestly), games-with-lineup count + best reused-lineup fact when present. Every stat carries a "has enough data" flag — a 3-game season renders a smaller honest card, never fake superlatives. Sport-neutral vocabulary via Sport Pack (no "innings"/"runs" hard-codes).
- [ ] **2.2 Wrapped API + card.** GET endpoint via the 1.4 resolver (works for the just-closed year AND any past year). The card itself is a shareable-looking, team-colored highlight layout (portal-side, warm-theme aware, team color as accent under the existing team-color guard rules) rendered on the Season's End page; each stat is a tile; tap-through into the relevant Insights report where one exists.
- [ ] **2.3 Share as image (per D3 — recommended).** "Share your season" button → client canvas render (reuse the `lib/share-card.ts` pattern: branded PNG → Web Share sheet / clipboard fallback). The coach chooses where it goes (family group chat, social) — no new public routes, no PII beyond what the coach already chooses to share (first names + jersey numbers only on the award line; decide exact fields at mockup review). A no-login family LINK is deliberately deferred (needs new public/token plumbing — noted for a future batch).
- [ ] **2.4 Wrapped placement (per D4 — recommended: automatic, plus on demand).** (a) The Season's End landing leads with it (club coaches see it the moment the admin closes the year — the lockout becomes the ceremony). (b) The standalone rollover success screen gains a "See your Season Wrapped" link to the just-closed year's card. (c) The Insights hub gains a per-past-season entry point (small "Season Wrapped" link beside each archived season in the results archive switcher). The Overview `result`-phase card (now reachable for the window where a season is completed but a new one exists) links to it too.

### Phase 3 — The "you're probably done" cue (P1 f5-1)

- [ ] **3.1 Trigger (per D5 — recommended thresholds, tune at mockup review):** season is `active` AND ≥1 finalized game AND nothing scheduled ahead AND ≥14 days since the last event AND no upcoming registered tournament. Computed from data the Overview already fetches — no new endpoint. The 14-day floor keeps mid-season breaks and tournament gaps quiet (`hasUpcomingTournament` already suppresses it).
- [ ] **3.2 Rendering:** a quiet, dismissible inline card on Overview (below any anchor, above content — never a modal, never a toast): "Looks like the season may be winding down." **Standalone head coach:** primary action → "Close out the season" (opens the existing Start-next-season modal — which is ALSO the close action; copy in 4.1 makes that honest). **Club coach (all roles) + assistants:** informational variant — "When {org} closes the season you'll get your Season Wrapped here." Dismiss = snooze via `localStorage` (per team+year); any new future event auto-clears it.

## Architectural decisions (proposed — ratify with the mockups)

- **Closed seasons are a separate, explicit, read-only surface — the general active-season gate is never widened.** *Rationale:* the write inventory shows widening the assignment filter either 404s by accident or silently routes writes to the wrong season; ~49 routes assume "visible = writable." An explicit closed-context resolver keeps the entire write surface untouched by construction.
- **The Wrapped computation is ONE pure server-side function, and it becomes the canonical season-record rule.** *Rationale:* the record is currently tallied three ways with two different game-type sets; a celebration card that disagrees with the Insights page a tap away would be worse than no card.
- **Wrapped shares as an IMAGE through the OS share sheet, not a link.** *Rationale:* reuses the proven score-card canvas pattern; a no-login link requires a public/token read path the portal has never had — a security-relevant feature deserving its own batch, not a rider on a celebration.
- **The winding-down cue never renders while anything is scheduled or a tournament is upcoming, and dismissal is per-season.** *Rationale:* the review's own worry — nagging a team on a mid-season break — is the failure mode; silence until the evidence is strong, one dismiss ends it.
